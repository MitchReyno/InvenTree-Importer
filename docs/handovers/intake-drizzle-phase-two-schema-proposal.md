## Exact mapping contract

All columns below are present in the reviewed migration SQL. Property names are camelCase with explicit snake_case SQL names. UUIDs and text remain strings; bytea remains Buffer using the existing `customType`; PostgreSQL integer remains number; every bigint uses `{ mode: 'bigint' }`, with exact decimal string conversion at established API/domain boundaries. Timestamptz uses timezone-aware timestamp/Date as phase 1. Nullable fields stay nullable; omitted defaults mirror migrations exactly.

Primary and composite key column sets match the migrations. No generated migration, `.references()` graph or duplicated authority constraints are introduced; SQL still owns composite/deferred foreign keys, unique/check constraints, indexes, triggers and grants. `mapping` stays untrusted JSON until the existing runtime validators establish its shape; the declaration must not assert a stronger type than validation proves. Enum-like text may use the existing migration-constrained unions only where every migrated value is included.

## Behavior and query boundaries

Use the existing `queryDatabase`/`executeDatabaseQuery` adapter on the exact caller-supplied connection. No new connection checkout, transaction, retry, implicit relation query or altered statement order. Keep explicit SQL for locking/upsert sequencing, compare-and-set/increments, aggregates/recursive/multi-table existence probes, transaction commands/grants and `public.`-qualified authority reads. Preserve missing-row refusal and left-join nullability.

The ACK covers these declaration names/ownership/type rules and ordinary deferred query conversion. It grants no new inventory authority, database schema change, provider access, new HTTP contract or permission to modify protected data.
