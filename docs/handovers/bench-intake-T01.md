## Decisions and rejected alternatives

1. **Runtime schemas, strict JSON and generated first-slice examples (owner, T01).** TypeBox/AJV Draft 2020-12 validates without coercion/defaults/stripping; the Fastify parser first rejects invalid UTF-8, decoded duplicate keys (including equal values), prototype keys, unsafe/nonfinite numbers, comments/trailing commas, depth over 64 and bodies over 256 KiB. Complete response DTOs validate before serialization, so private-field leaks fail rather than silently strip. Safe public errors suppress original bodies/messages.
2. **Reject lossless-json for this parser (observed experiment).** It accepted equal-valued duplicate properties, which violates the boundary. Replaced it with jsonc-parser 3.3.1's visitor plus `JSON.parse`; equal-object/equal-scalar and escaped-alias regressions remain. No weakened duplicate policy.
3. **Reproducible DTO/OpenAPI/client generation without changing TS (observed compatibility).** openapi-typescript 7.13's peer range rejected the existing TS 6 toolchain. Replaced that option with json-schema-to-typescript 16.0.0 and a generated validating two-GET client, rather than disabling strict peers or downgrading TS. OpenAPI lists only executable GET routes; future command shapes are components, not fictitious endpoints. Generation drift is checked, not auto-written in CI.
4. **Reviewed SQL over schema push (plan + owner).** Drizzle provides inferred access types, but reviewed migration SQL owns cycles, constraints and append-only triggers. Migrations serialize under an advisory transaction lock and verify retained SHA-256. Administrative DDL is trusted and can bypass triggers; do not claim otherwise.
5. **Keep DBOS after bounded public-API qualification (observed real PG/process).** Public retained metadata/input is sufficient to reject changed full payload, queue, function/class/config or version before ACK. A name collision may throw on enqueue, so the adapter inspects public state rather than parsing exception text or DBOS tables. No custom runtime alternative was needed. Handler execution checks actual build version independently of scheduler metadata.
6. **One bounded shared development PG (explicit user authorization + inspected resources).** Reuse existing postgres:17 image, one owned container/volume and restricted per-purpose roles. Random test DBs isolate mutable state without starting a stack per worktree. Optional InvenTree image inspection was network-disabled and sufficient for version/startup notes; a full inventory stack was unnecessary for T01.
7. **Non-runtime tooling `.cjs` (explicit latest user instruction).** Root CODE_GUIDELINES explains unambiguous CommonJS under `type: module`, direct Node execution and avoiding a separate transpiler/runtime loader/bundler configuration. `contracts/scripts/generate.cjs` and `intake-server/scripts/dev-services.cjs` follow it; declared dependencies still apply. They intentionally consume runtime TS schema/grant modules via pinned Node's built-in erasable-type support, not duplicated policies. Runtime TS, typed application test modules, Python/shell and established framework ESM configuration were not gratuitously converted.

## Migrations, roles and exact retained bytes

`intake-server/migrations/0001_foundation.sql` SHA-256: `10c61702d9220dc23fa3a414c3215d1c7219bfda18f52f0f5cb6205bbf8d8485`. Do not modify a migrated file; coordinate subsequent IDs/migration order through the coordinator. Target/current-context cycles use deferred composite FKs; commands cannot point at another target's context. Digests enforce length 32; command/context/idempotency/event authority rejects UPDATE/DELETE. Runtime grants exclude DDL, identity/target rewrites and retained-authority updates; stream updates are restricted to `head`. Migrator/database administration remains trusted.

`idempotent` requires a caller-owned transaction and serializes missing/present logical keys using an advisory transaction lock. It compares canonical payload bytes in addition to their digest and replays retained response bytes only for identical semantics; changed payload conflicts. Different property order is equivalent; ordered arrays and Unicode text remain exact. Domain and dedup writes commit/roll back together. Future DB commit-ACK uncertainty must be inspected through stable authority, never automatically retried as a remote operation.

Canonical v1 sorts object keys by JS code-unit order, preserves UTF-8 human text/arrays and permits only exact string/boolean/null scalars; number/undefined/custom-object inputs reject. The independent Unicode vector in `contracts/vectors/canonical-v1.json` supplies expected hex and SHA-256; tests compare original bytes, digest and real PG bytea round-trip, not JSONB reserialization. pg bigint/numeric stay strings and Drizzle bigint mode stays native bigint. A real `numeric(19,6)` fixture proves exact minimum/maximum/asymmetric values and boundary rejection before PG could round excess precision. This numeric fixture and same-batch/wrong-job cycle fixture are **test-only representative DDL**, not implemented domain catalogue tables.
