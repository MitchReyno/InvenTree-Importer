# Commit hooks, Markdown tooling and aggregate CI

## Scope and ownership

Mitch requested a separate PR based directly on `interactive-app`, adding lightweight pre-commit checks, a single aggregate CI check, advisory lint CI and remark formatting/linting. This work is isolated on `ci/pre-commit-and-required-gate`; it does not depend on the Bench Intake spike branches or change importer execution, inventory, provider authentication or shared fixtures. Preserve all other worktrees and local data. No merge or branch-protection change is authorized.

## Decisions and alternatives

- Use the established pre-commit framework, installed through the backend development group and lockfile, rather than a custom Git-hook dispatcher or another JavaScript hook framework. Root pnpm commands install or manually run hooks. Installation is deliberately explicit: linked worktrees share Git hooks, so this change does not install hooks into the user's common Git directory while other owners work.
- Pin upstream basic hooks to the `pre-commit-hooks` v6.0.0 commit. Check merge markers, JSON/TOML/YAML syntax and large added files. Allow multiple YAML documents because the pinned pnpm generates a multi-document lockfile. Do not add whitespace fixers that might rewrite byte-bound evidence.
- Reuse the configured Ruff for changed Python files and the existing frontend ESLint script when frontend source changes. ESLint checks the small frontend scope rather than duplicating path-rewriting logic for pre-commit arguments. No test, build or typecheck command runs in the commit hook.
- Add pinned root-only remark development dependencies, recommended lint rules, GitHub-flavored Markdown and YAML-frontmatter support. Retain one physical line per prose paragraph; remark introduces no fixed-width wrapping. The staged Markdown hook formats and lints; developers inspect/restage modifications. Whole-repository lint is read-only and fails on warnings; whole-repository formatting is an explicit separate command. Both respect ignored local data and exclude local worktrees/review artifacts. No mass reformat of existing documents is included.
- The remark hook ends its option list with `--`: its `--output` flag accepts an optional path, so without the separator the first staged filename could be consumed as an output destination for empty stdin. An actual disposable-repository probe exposed this during development; no user files were affected. The corrected command processes staged filenames as inputs.
- Move Python/frontend lint out of the blocking jobs into one `lint` job and add Markdown lint there. Do not set `continue-on-error`, which would hide a failed job. Later frontend/Markdown lint steps run even after an earlier linter fails unless cancelled. The job remains visibly failed when any linter fails but is not a dependency of the aggregate gate.
- Name the aggregate check **CI**, require backend/frontend jobs, and run it with `always()` so failure/cancellation/skipping cannot silently skip the gate. Its command requires both dependency results to equal `success`. Repository rulesets must require this check rather than lint or the entire workflow; changing those shared settings is not part of this PR.

## Limitations and continuation

Hook installation requires the declared uv/Python and Node/pnpm tools and installed application dependencies on PATH. First use downloads the pinned basic-hook environment. Hooks are a local development guard, not a replacement for CI or an inventory authorization boundary. Git can bypass hooks explicitly; the PR does not modify existing common hooks or global Git configuration.

The workflow may be red overall while the required CI check is green because lint is advisory. Existing rules requiring individual legacy jobs or all checks may still block until a human deliberately updates those settings. No repository protection settings, external workflows, deployments or live inventory were changed. Independent pre-publication review is complete; publication targets `interactive-app`, with hosted CI results reported separately. Nothing here authorizes merging.
