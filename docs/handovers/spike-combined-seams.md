## 3. Decisions, alternatives and acceptance details

1. **Retained observation replay, never oracle substitution** — user requirement, implemented 2026-11-01. The primary source of proposal bytes is `spikes/subscription-runtime/observed/proposal.json`; the expected file is used only in an offline inequality control. Original provider omissions are not repaired by fabrication. Shared evidence is fictional, while the proposal/question observation was actually provider-produced historically.
2. **Reuse public engine/adapter/coordinator seams** — user preference and owner choice. Reuse strict message/artifact decoding, existing Intent/Job/Question/Emission/Outbox models, `insert_intent`, `check_owner`, `accept`, adapter preparation/materialization/load/start-adopt, supervisor cancellation/status/selected repair, persistent fake and canonical `inspect_binding`. Do not copy engine registry SQL, mutation handlers or native provider runtime internals. New command transactions bridge fixture-specific facades that cannot accept this retained provider input unchanged.
3. **PostgreSQL is approval/command authority** — Stage 1E requirement. The new Approval/ApplyOutbox models and migration compose with the existing coordination migration graph. Approval and outbox rollback together; the adapter transport file does not exist after commit-before-dispatch. Stable content-addressed approval identity deterministically selects the original canonical location. There is no distributed transaction across PostgreSQL, importer SQLite and the fake target.
4. **Outbox plus metadata comparison, not unconditional workflow retry** — retained 1B decision. Verify persisted actual workflow/version/queue/class/config/full arguments before ACK. Correct ID with wrong digest reaches ERROR without inventory; wrong runtime version stays ENQUEUED under its incompatible version, explicitly conflicted and unacknowledged. No incompatible worker is run in this new proof, and that unrun path is not execution coverage. A healthy authored command still finishes after both conflicts; repeated dispatch preserves both dispositions.
5. **Fail closed on child failure and canonical reservation gaps** — user requirement. A separate real SDK child is SIGKILLed at the actual post-registry-reservation/pre-journal constructor boundary. Only the constructor is replaced by the authored kill hook; reservation and persistent canonical authority are genuine. The public inspection seam finds its original run with `recovery_required` and no snapshot; ordinary redelivery cannot allocate a replacement namespace. A run directory need not yet exist at this boundary.
6. **SDK cancellation/IPC controls are explicit authored controls** — owner bounded test choice, not new provider observations or a production supervisor. Cancellation and blocked-observer controls start a real supervised child from an already committed PostgreSQL approval. A durable DBOS delivery racing the surviving original child is excluded and records recovery-required, then canonical reconciliation publishes the settled original. This directly exercises the asymmetric surviving-child boundary rather than mocking the SDK. The cancellation pipe prevents later mutation after an already accepted stock request, without undoing that stock. Blocking the real event consumer produces nonzero datagram drops while canonical execution still completes; durable delivery adopts that original run afterward.
7. **Selected repair remains explicit engine authority** — user requirement. Initial unknown stock/attachment journeys dispatch through the real PostgreSQL outbox/DBOS/SDK path. Subsequent selected repair and later-round execution after supported attachment settlement use explicit existing supervisor controls against the original PostgreSQL-exported approvals and canonical run; they are not a new durable application repair-command implementation. Unknown stock remains unresolved even after an authored external deletion in the owned fake; supported repair issues no replacement stock POST and the earlier claim still blocks lot B. Attachment repair verifies retained bytes without another attachment, retains the historical unknown attempt/request and then permits the already approved original lot B.
8. **Separate bounded investigation dependencies** — owner default. Combined Python 3.12 dependencies are isolated in a new lock, not added to backend. Actual combined versions include pint 0.26.2 and pypdf 6.21.4, distinct from backend's normal locked 0.25.3/6.21.0. The complete combined lock/source fingerprint is bound into each approval in addition to the adapter/importer build digest; these are observed investigation resolutions, not recommended final production pins. Changed code/resolution rejects historical commands rather than migrating them.

Rejected alternatives: promoting the fixed synthetic runner, replacing the actual provider proposal with expected-stock, rewriting languages/services during the pending decision, assuming DBOS duplicate-ID enqueue compares all metadata, using SQLite/mock commits as PostgreSQL durability proof, allocating fresh source/state roots on uncertainty, payload-matching unknown stock, treating lost progress as execution failure, automatically replaying mutation steps, and adding browser/HTTP/auth/SSE implementation merely to demonstrate command-side seams.

No acceptance requirement was silently dropped. The primary evidence-to-approval-to-dispatch-to-canonical journey is connected; adverse controls intentionally branch into separate new fake targets/private state so one deliberately unresolved claim cannot invalidate unrelated observations. Each branch keeps its own original state/source/Part/contribution identity through recovery; a new branch is not a retry namespace for an uncertain run. Authorizations, cancellation/selected repair and wrong-version unrun behavior are distinguished above rather than presented as production or native provider coverage.
