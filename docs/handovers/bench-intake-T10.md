## Implementation approach

Reuse existing streams/events and snapshot DTOs; SQL migrations remain authority. Prefer no schema migration or new tables unless inspection proves a requirement. Add typed shared live protocol schemas and generated artifacts only through maintained contract tooling. Keep server live transport, read projection, operational files and browser cache coordination in separate owning modules. Use current exact decimal scalars, same borrowed connections and no retry for uncertain writes.

For backup, use a consistent PostgreSQL snapshot with explicit locking/quiescence and immutable retained blobs. Include scheduler schema on the same database or refuse unsupported separate topology rather than fabricate coherence. Export only safe configuration/identity metadata; operators separately provision credentials. Every output is exclusive/private and finalized only after byte/hash validation. Do not automatically clean partial archives: preserve them as incomplete evidence. Restore starts from new empty owned paths and never overwrites a retained database/blob root. Preserve independent external witnesses so the existing gate detects missing post-backup intents.

## Implemented decisions

WebSocket packages are pinned to `@fastify/websocket` 11.3.6, `ws` 8.22.1 and development types 8.18.2, verified against the registry and [Fastify WebSocket documentation](https://github.com/fastify/fastify-websocket) / [ws documentation](https://github.com/websockets/ws). The first frame is authenticated with the existing development bootstrap token; it is never put in a URL. Route hooks reject wrong Origin/Host before upgrade. A real refusal test exposed a dangling raw rejected-upgrade socket: the root HTTP response hook now destroys sockets for completed upgrade refusals, including requests rejected before plugin hooks. Valid upgraded sockets remain outside the normal HTTP-response lifecycle.

The channel has eight-connection, 16KiB input, 64KiB queued-output and five-minute lifetime limits. A 10-second heartbeat checks liveness; the browser watchdog and capped reconnect restore polling. The server reads scoped heads once per second, checks at most 128 retained event sequences for catch-up and sends coalesced exact cursor hints rather than journal payloads. Missing/over-window/future history resets through a fresh retained snapshot; it never replays execution. Up to 100 streams are tracked with selected-batch priority; truncation keeps a 15-second safety poll. This reduces browser HTTP traffic, not database truth validation. Native sockets are separate from lossy provider progress.

Manual start/cancel/recovery and runner state changes publish stream hints last in the same domain transaction. The runner receives only the existing narrow projection grant; no source enrollment or apply authority was added. Readiness uses strict shared response schemas/generated policy and read-only migration access in the API foundation grant. Web startup refuses drift before application route registration and emits fixed redacted JSON events. Existing startup fixtures now consume the explicit JSON ready event and allowlisted safe refusal codes; no deadline was widened.

Archive supports only app and scheduler in one local database. Table share locks plus an exported snapshot and verified immutable blobs establish the archive cut. Native pg_dump/restore subprocesses have bounded stderr/output/deadlines and no credential argv. Archive manifests record migration/store/digest identity and exclude credentials/config files/external activation/witnesses/claims. Every destination is exclusive/private; partial failures remain for inspection. Restore only accepts a fresh empty `intake_restore_*` database and new canonical blob root, verifies bytes and returns quarantined with external activation still disabled. No retention/deletion/unpinning feature exists. The CI steps explicitly name their own PostgreSQL service container for the portable native-binary test adapter; local tests reuse the lease-owned service.

The frontend's collapsed local setup/diagnostics panel reads readiness only when opened, shows development-mode/provider gates honestly and offers explicit rechecking. It has no credential entry or configuration mutation. Live hints invalidate retained query caches while form drafts, pinned selections and command acknowledgements remain domain-owned. Autosave/agent-dialogue command transport is future work; existing HTTP commands remain explicit and never resubmitted by a reconnect.
