# Planned functionality details

This directory is reserved for detail files referenced by the [planned functionality register](../PLANNED_FUNCTIONALITY.md). It currently contains no registered items.

Copy [TEMPLATE.md](TEMPLATE.md) to `BI-NNN-short-slug.md` when adding an item. Assign the next unused numeric ID after checking the register, detail files and Git history; preserve IDs and filenames when changing titles. The template is guidance, not a registered item.

Keep one distinct deliverable per file. Include the current metadata, problem, intended outcome, scope, acceptance criteria, prerequisites and known open questions. Use relative links to repository evidence and complete URLs for external references. List unknowns explicitly rather than inventing estimates, approvals or implementation claims.

Use the project-level `planned-functionality` skill for additions, changes, deduplication and status maintenance. Update the index and detail file in the same PR. Keep current state only; do not add status histories or dated progress logs.
