# Frontend architecture

This document describes the implemented manual intake application under `frontend/`. Read the [shared architecture](../ARCHITECTURE.md), [shared guidelines](../CODE_GUIDELINES.md) and [frontend guidelines](CODE_GUIDELINES.md) for its boundaries and change policy.

## Current application

React and TypeScript run in a Vite browser application. `index.html` loads `src/main.tsx`, which mounts `App` under React StrictMode. `src/App.tsx` uses the validated generated contracts client against the same-origin Fastify API. Bootstrap supplies development-mode attribution and an ephemeral CSRF token, never an inventory key. Retained batch list/create/read/edit/archive commands store state in PostgreSQL, not localStorage. A hash URL retains batch and selected subject/editor; refresh loads saved server state. Closing the browser does not erase batches or notes.

`src/components/capture/CaptureWorkspace.tsx` coordinates the header, evidence column and Batch settings column, each in its own `.tsx` file. Batch list/detail components live in `src/components/batches/`; retained data/client types and pure display mapping stay in `src/capture/`. Capture has no Physical lots or Part proposals panes; manual subject create/edit, Part choice and attachment choice open in Review's focused `ReviewSubjectEditor`, which reuses `CaptureEditor` and the existing capture commands. Shared Part proposals never combine physical lots. Exact quantity and PK strings stay strings; notes visibly identify human provenance. Defaults and explicit lot selections retain unset/unknown/clear/inherit/set distinctions. Reading a configured target's existing Part/location creates an observation; selecting it is a separate human action. No browser command accepts a target URL, actor or inventory secret. Capture fields support manual quantity, location, existing Part choice, labels, links and append-only notes; retained media has its own boundary below.

Each save carries the loaded batch revision. A 412 preserves local inputs and displays current saved values; explicit discard/reload is required, never silent rebase or last-write-wins. A single dirty editor disables subject navigation/archive, with explicit discard. The app-owned navigation guard receives synchronous dirty callbacks from Capture and nonempty new-batch title/note forms. It blocks same-document links and hash/history route acceptance while retaining the mounted form and exact input; native unload is protected too. Save/create or explicit discard releases the guard. Transient review selections/archive filters do not lock navigation. A failed/uncertain save remains visibly unconfirmed; it is not blindly retried. Archive retains history and disables editing until explicit resume. Review, Approve and Results use the generated manual client; Processing exposes retained jobs and questions through its retained coordinator and explicitly selected fixture/native profiles. Retained uploads and crop preparation are described below. Native provider sessions require a separately supervised worker; there is no Python runtime connection.

Capture exposes one `BatchSettingsPanel` in the right column, stacking below evidence under 860px, with one mounted RHF draft. It holds the title, optional batch notes, one Default location, supplier (No supplier, existing or new draft), the disabled purchase-order preview directly below supplier, Shared part tags and Custom instructions; Quantity mode is gone from the panel and per-lot exact quantities stay in Review. Write a note opens an inline append-only evidence note in the evidence column. Lot editors preserve explicit context overrides; Capture and Review label effective human context separately from approved inventory effects. Saved inheritance/override details are a collapsed summary below the panel. Placement comparison and native 200%/360px/390px evidence are in [the settings qualification](../docs/bench-intake/evidence/capture-settings/README.md).

Capture's editor and the separate `components/batches/NewBatchForm.tsx` use pinned React Hook Form. Native fields register directly; Controller adapts the existing quantity/reference controls without changing their modes or exact string values. `capture/editor-model.ts` owns initial values and command construction. Editor defaults remain fixed for the mounted selection, so newer snapshots do not reset a human draft. Synchronous event callbacks still feed the application navigation guard. The form package does not own revision authority, uncertain acknowledgements or payload-bound delivery keys; new-batch creation and Capture edits preserve revision/payload-bound retry intents independently of form submission state. After an unconfirmed edit, a changed payload requires explicit saved-state reconciliation; exact unchanged retries reuse the original key. The settings panel has no Save button: `capture/save-queue.ts` is a per-batch serialized owner for the `batch_settings`, instruction and logo-upload commands. Valid edits send after a 500 ms idle debounce or on blur, and freeze payload, expected revision and key per request; later edits are sent against the acknowledged revision. IME composition suspends every dispatch until it ends, and a disposed queue never dispatches. While a lane's request is unconfirmed, every newer draft is kept, including one equal to the old saved value. Conflicts and uncertain acknowledgements block further commands until an explicit keep, exact retry or discard-and-reload. A clean panel adopts newer saved values; a dirty one never resets. Editing needs a fresh scoped observation (the shared header connection read or the batch's capture read, succeeded within 60 seconds and not now failing) and an online browser; reconnection reads current state before admitting writes or exact retries. Evidence media, evidence note and settings commands do not overlap: each is fenced while another is unacknowledged, and settings stay paused after an evidence change until the read of its new revision is accepted (a failed read keeps them paused, with an explicit refresh). While disconnected, unsent drafts can be discarded locally; sent or unconfirmed requests keep their own recovery. A newly observed instruction version becomes that lane's saved baseline and text unless the lane holds a draft or an unacknowledged request; adoption never sends. Only the newest post-evidence refresh releases or fails the settings gate. Supplier and location observations apply only while their choice is the newest intent of a mounted field, against the form's current drafts. Typed tag text that has not been added keeps navigation protected. Dirty owners report clean only on unmount or confirmation; a replaced parent callback receives the current state.

`components/review/ManualWorkspace.tsx` coordinates retained reads driven by live hints, bounded polling fallback and explicit commands. Review presents physical-lot selection, human evidence and exact saved choices; selecting a shared Part never includes another lot. The first slice accepts at most ten selected lots. The approval view shows included/excluded lots, reused Parts, exact stock effects and the frozen plan digest. Its URL pins the preparation identity across polling/reload; removed or stale plans disable approval instead of substituting another latest plan. Replacement requires explicit choice. Selected/shared dependency changes require fresh review/preparation; unseen capture changes disable review until explicit reload.

`components/results/` displays original approval rounds and journal certainty. Approval and queueing are separate actions. Unknown outcomes have no create-again control; cancellation cannot undo an authorized request. Only server-advertised original-operation recovery is offered. App-wide activity is a bounded, explicitly truncated retained-run snapshot, not simulated progress. Commands carry neither browser authority nor inventory credentials.

Module-scope styled-components declarations own the light/neutral palette and blue selection explicitly approved by Mitch. Shared controls/panels/text live in `components/ui/primitives.tsx`; `GlobalStyle` contains only document/reset/font/focus defaults. Styling-only state uses transient `$` props. The legacy stylesheet is removed. Layout/UX follows the primary [original HTML prototype](../docs/bench-intake/reference/bench-intake.html), [Capture](../docs/bench-intake/reference/03-capture.png), [Review workspace](../docs/bench-intake/reference/02-review.png), [Inbox](../docs/bench-intake/reference/01-inbox.png) and [phone frame](../docs/bench-intake/reference/10-phone.png); see the [reference index and historical limitations](../docs/bench-intake/reference/README.md) before the secondary derivative board. Authoritative [experience wireframes](../docs/bench-intake/05-experience.md) and latest contracts override prototype simulations. Capture follows the original two-column hierarchy: evidence actions and groups on the left, Batch settings and Go to review on the right, one column on narrow screens. Review keeps queue/evidence/decision. No fake media or simulated processing/execution is added to mimic unavailable breadth. Approval and Results also follow the original [approval](../docs/bench-intake/reference/08-approval.png) and [results](../docs/bench-intake/reference/09-results.png) hierarchy.

`components/masthead/Masthead.tsx` owns the brand header: the "Bench Intake" title with its `Dev mode` badge, the scoped status action slot and the optional child navigation slot over a faint dot grid. `ElectronicsCurrent.tsx` adds a decorative, `aria-hidden` canvas of isometric outline-style electronic parts drifting right to left behind the title. The pointer stirs nearby parts, and switches react to it. The canvas never fetches, writes or touches application state. Its scene logic lives outside the component tree in `src/electronics-current/`: palette, outline material kit, part builders by family, weighted catalogue, pure flow maths and the scene controller. The component feature-detects WebGL 2 before dynamically importing that scene chunk, so unsupported browsers and jsdom never download three.js and keep a plain masthead. `prefers-reduced-motion` renders a single static frame without an animation loop. Unmounting cancels a pending start, the loop, the resize observer and all GPU resources. The part count scales with masthead width; narrow screens dim parts under the text instead of hiding them. Planning, package assessment and browser evidence are in the [masthead animation handover](../docs/handovers/bench-intake-masthead-animation.md).

`src/App.test.tsx` covers exact string emission, human attribution, archive/resume and concurrent-edit conflict through a jsdom/component boundary. Actual loopback server/browser/restart and inspected desktop/narrow/nondefault screenshots are recorded in the [T02 handover](../docs/handovers/bench-intake-T02.md); component tests alone are not browser or production-access qualification. `ManualWorkflow.test.tsx` adds exact selected/digest emission, explicit stale-display reload and unknown-result controls. The [T04 handover](../docs/handovers/bench-intake-T04.md) links actual desktop/narrow manual journey evidence.

## Design alignment and evidence inspection

The shared masthead, `Dev mode` badge, status disclosures and batch header use compact spacing so working evidence appears earlier on desktop and phones. At desktop widths the title/counts and stage navigation share a row; narrower layouts stack them. All five stages, practical 44px controls and attribution remain visible. On narrow screens the labelled lot-filter strip scrolls within its own row, selection actions share two columns with wrapping labels, and desktop-only shortcut hints are omitted; safety/read-state notices remain visible. The explicit `#<batch>/capture` route opens Capture; legacy `#<batch>/<subject>` links redirect to Review (`#<batch>/review/<lot>?edit=<lot>`, or `?edit=<part|add_lot|add_part>`) through the normal navigation guard.

`components/batches/Batches.tsx` presents a recent-batch card and compact saved list with explicit stage links, retained thumbnails and workflow observations. The recent batch appears only in its Continue card until searching, when it participates in matching results. Server-wide title search, archive inclusion and ten-row paging use one validated read. `BatchStageLinks` owns stage navigation; `BatchWorkflow` presents observations rather than command authority. See the remaining mockup composition below.

`components/operator/EvidenceViewer.tsx` displays linked retained source/version/page choices through the existing object-scoped preview route. Selection pins evidence ID, version ID, page number and preview ID for that focused lot lifetime. Polling never substitutes a newly added version or a changed/missing page; unavailable selection requires an explicit choice. Changing lots remounts the viewer. Bounded zoom and keyboard-scrollable overflow inspect the retained preview without changing original/approved bytes. A pending first media read is visibly loading; a failed first read explicitly leaves file presence unconfirmed. Failed reads with cached media label the last retained snapshot; failed preview loads offer only a retry of the selected preview. Exact source/version/page/preview query fields persist inspection across reload; zoom remains local to this viewer.

`LotEvidence` places the image immediately after its evidence heading, with source/page/zoom controls and retained human notes below. Repeated lot/Part introductions are omitted; the queue and decision panel retain that identity. Fixture candidates remain below the human evidence. The Decision panel names an explicit new shared Part create accurately and offers candidate comparison only for existing-Part choices. No presentation action prepares, approves or changes evidence.

## Retained read coordination

Pinned TanStack Query coordinates bootstrap, batch reads, manual workspace and activity. The generated AJV-validated client façades remain the transport boundary. `queries/client.ts` explicitly disables retries and focus/reconnect refetch; manual/activity observers poll every two seconds. Loopback reads attempt even when browser connectivity reports offline. Existing client deadlines still bound requests; cache cancellation does not claim physical cancellation of non-abortable ports.

`components/query/ServerStateProvider.tsx` owns an in-memory cache. App separates bootstrap from the private cache and keys its lifetime by origin, actor, target and target-context IDs. Scope replacement cancels and clears the previous private cache; no browser persistence is installed. `useServerScope()` and `serverQueryKey(scope, ...resourceIds)` provide the shared seam for additional readers.

Cache data is an observation, never edit or command authority. Capture retains its accepted loaded snapshot until a confirmed save or explicit reload. React Hook Form drafts, dirty navigation, pinned preparation identity, review selection, last preview and payload-bound delivery intents remain outside the cache. Repeated reads cannot reset them. A cached manual preview stays disabled until the mounted observer verifies a read; failed or paused reads retain history while disabling freshness-sensitive commands. Confirmed commands and subsequent failed status reads have separate outcomes.

`ServerState.test.tsx` verifies scope isolation and late prior responses. App/manual component tests cover deduplication, periodic recovery, paused reads, accepted revisions, retained drafts, pinned preparation identity and lost acknowledgement. The [server-state handover](../docs/handovers/bench-intake-server-state.md) records actual browser evidence and package qualification.

## Retained media and crop state

Bootstrap exposes optional media capability only for an initialized, explicitly configured
private store. App supplies the generated media client only when that capability is true.
Media components keep original bytes, request keys/revisions and crop identities outside the
observation cache. Failed, paused or unfetched-this-mount reads disable new media commands
without resetting pending input. Capture and media dirtiness remain separate.

RHF coordinates group and frame/aspect forms. Moveable controls only the crop overlay;
the normalized source image stays fixed. Exact rational source dimensions correct CSS
rounding before server validation. Prepared output is gated by the submitted derivation ID
and exact recipe. An uncertain request retains its identity; explicit new-crop selection
creates a new intent using the current successfully read revision.

The crop dialog portals to the document body so responsive hiding of Capture context cannot hide an open modal. Native close events also reconcile the React editor lifetime: unsent or confirmed views close through the parent, while pending or uncertain requests keep their exact intent and reachable retry/discard controls.

Desktop follows the original crop editor/result hierarchy; narrow screens stack them. Existing reference bytes and the light/neutral/blue palette remain unchanged.

Prepared approval and results show exact attachment identity, source provenance and destination; they never choose a current/latest replacement implicitly.

## Tooling and application ownership

Frontend dependencies and scripts live in `package.json` here. Root pnpm owns the workspace/control point and single lockfile; `.node-version` and root `packageManager` pin the toolchain. React/Vite/TypeScript/styled-components/plugin versions are pinned in the frontend manifest, as is three.js, which renders only the decorative masthead in its own lazily loaded chunk; Python dependencies stay entirely in backend.

`vite.config.ts` configures React, a strict loopback development host, disabled dotenv discovery and Vitest with jsdom plus `src/test-setup.ts`. Source-byte hashing suppresses unchanged-source HMR. Root `pnpm dev` starts the [retained local app](../docs/development.md): a separate Vite child owns the public HTTP/WebSocket proxy while the supervisor drains/restarts API and workers on server/contracts edits. Standalone `pnpm dev:ui` has no API proxy. Use `pnpm build` and `pnpm dev:intake` for the standalone built UI/API; the server serves only built `frontend/dist` through `@fastify/static`. The frontend does not load root inventory/vendor credentials. No credential belongs in client-exposed Vite variables. `tsconfig.json` enables strict checking; `eslint.config.js` provides configured lint rules. A successful build does not deploy anything.

From repository root, `pnpm dev`, `pnpm typecheck`, `pnpm lint:frontend`, `pnpm test:frontend` and `pnpm build` delegate to this application. Root normal tests also run backend checks. See [repository layout](../docs/repository-layout.md).

## Operator review workspace

Review is an evidence workspace over the same retained facts; it adds no second truth model. `Batch` reads the `OperatorReview` projection through `operatorReviewClient` beside the capture snapshot, and shows it only when its revision matches the accepted batch revision. Retired lots stay in the capture snapshot for history, but Capture, Review selection and new Processing attempts hide them. Processing job history for a retired lot stays visible.

`components/review/ReviewWorkspace.tsx` coordinates the Evidence and Table modes. The URL holds the focused lot, the mode and the filter (`#<batch>/review/<lot>?view=table&filter=warnings`); transient selections do not. The queue groups active lots by urgency: blocking, warnings, changed after review, needs review, reviewed, approved. Pure filter, grouping, URL and provenance rules live in `src/operator/review-model.ts`.

Components under `components/operator/` own focused responsibilities:

- `LotEvidence` shows lot, Part, batch and predecessor-lot notes, linked media previews and Processing proposals labelled fixture-only. Proposals are candidates, never chosen values.
- `DecisionPanel` shows fact rows with provenance (human set, inherited default, override, unknown, cleared, unset), the lots sharing a Part proposal, blocking problems and warnings. `CompareMatches` sets observed Part candidates side by side and confirms the shared edit with the exact affected lots before the capture edit. `QuickLotEdit` makes lot-only quantity/location edits.
- `IssuePanel` and `DismissWarning` record a reasoned dismissal bound to the warning's dependency digest. Blocking issues have no dismissal control.
- `TableWorkspace`, `ReviewTable` and `BulkEditPanel` provide the table projection, explicit row selection and bulk quantity/location edits. `RestructureDialog` splits, merges (with explicit same-contribution confirmation) and moves lots between Part proposals. Every bulk or structural change shows the server dry-run `ImpactSummary` first, then applies the same change.
- Batch instructions appear as Custom instructions inside Batch settings and autosave through the same queue; each evidence group owns its instruction form. Group/evidence context is retained human input, not an approved inventory effect.

`operator/useRetainedCommand.ts` binds one payload to one idempotency key. An uncertain outcome, including a typed server 5xx, keeps the exact payload and key for retry; a definite refusal or a revision conflict releases them. A conflict keeps local form input and requires explicit reload. Operator forms report native changes synchronously and aggregate dirty state by source, so closing a clean sibling cannot release another form's guard. Dirty drafts block internal lot/view navigation, editor closing and sibling commands that would remount them; explicit discard is available. A matching accepted operator projection keeps draft owners mounted if polling fails or discovers a different revision. New commands are fenced while it is unavailable, but pinned uncertain retries remain usable. Shared-Part comparison stays open after a resolved refusal and closes through the confirmed revision remount or explicit discard. Pending previews freeze their fields and discard late results after a form-generation change; later edits invalidate the preview.

Keyboard shortcuts (J/K move, R mark the focused lot reviewed, E edit quantity, V focus evidence) are ignored inside form fields, with modifier keys or while a dialog is open. Dialogs use native modal `<dialog>` and restore focus to the opener. Narrow screens keep the list → focused lot flow, and the table scrolls inside a labelled region rather than the page. `OperatorReview.test.tsx` and `OperatorSurfaces.test.tsx` cover these behaviours with injected fakes; native browser evidence is recorded in the [T08 handover](../docs/handovers/bench-intake-T08.md).

## Processing workspace

Batch routing keeps Processing separate from the manual inventory stages. Its
header and stage tabs preserve the app-wide dirty-input guard; question URLs pin
an exact question rather than selecting the latest question from polling.
Processing reads use the same actor/target/context query scope as Capture and
manual review. Commands require a successful mounted read; cached data alone
cannot establish answer or start authority.

The global indicator reports inventory runs and Processing lane occupancy
separately. A stale-input worker that still physically occupies the lane remains
visible as occupied. Processing activity failures are reported independently.
Actual provider integration remains unqualified; retained synthetic fixtures do not prove successful native login, entitlement or inference.

Media blockers retain job history and report unavailable input separately from occupied capacity. Proposal sources show exact note or evidence/version identities. The server supplies the raw selected-attempt cancellation capability, so a stale displayed input can still be cancelled when its exact attempt is cancellable; terminal attempts do not inherit that action from a display label. The command still carries its pinned revision and attempt.

Processing questions use React Hook Form without replacing the first pinned question/context on polling. Exact retry payload/key survives an unknown acknowledgement. Archived batches disable mutation while explicit local discard remains available to release the navigation guard. All research shown here is fixture-only; no model call or content inspection is implied.

## Live server updates

`components/operations/LiveUpdates.tsx` owns one scoped WebSocket lifetime beneath `ServerStateProvider`. Validated ready/change frames cancel older read publication before refreshing retained queries; hints arriving during that refresh are queued for another fresh read. No socket payload owns edits or executes a command. Exact cursor strings survive reconnect. Healthy channels suspend routine polling, disconnections restore the existing two-second fallback and truncated stream windows retain a slower safety poll. Focus/reconnect reconciles retained reads. Malformed/regressing frames and incompatible protocol versions require an update without clearing unsaved input. Bootstrap refresh after restart rotates development authorization; private actor/target/context changes still replace the entire keyed cache. Settings autosave uses HTTP commands only; agent dialogue requires separately reviewed command semantics. Connection establishment is never command acknowledgement.

## Remaining mockup composition

Search matches title text across retained server state before pagination; archive inclusion and literal wildcard characters are explicit. Typing alone performs no requests. The recent card and list show authorized original-page thumbnails, exact review observations, current Processing question/job counts and the latest original approval round. Missing media uses a labelled note/known-values placeholder; a failed thumbnail does not substitute unrelated evidence. Counts may overlap (a lot can need review and have a blocking issue); they are observations, never command authority. Failed list reads offer retry and do not claim an empty successful result.

Reload restores that exact page; malformed/partial links and missing/changed previews remain unavailable until explicit selection. Changing lot clears the previous lot's evidence link; mode/filter changes preserve it, including invalid pinned links. Zoom remains local. Saved work remains on the server; the URL contains no credential or approval authority.

Processing Overview adds linked stage summaries, and queues new attempts behind an explicit subject-selection disclosure. Images shows saved originals/documentary crops through the existing scoped media query and viewer, with links to prepare further crops in Capture. It does not choose attachments. Approve presents the exact frozen scope beside its effects and links excluded lots back to Review. These presentation changes enable no provider inference, autosave or additional inventory effects. ## Agent settings and sessions

The application-level `#settings` and `#agents` routes precede batch routing. Agent settings uses React Hook Form with one global provider/authentication/model selection, a pinned loaded revision, explicit save/discard and synchronous dirty navigation protection. Background reads do not reset its draft. API keys and subscription tokens have no browser input or response field.

Session history is scoped by origin/operator/target/context, paginated and invalidated by existing WebSocket projection hints. A ten-second reconciliation also covers history outside the bounded subscribed stream set; socket failure uses the existing fallback interval. Queued/active/completed/attention filters apply to each history page. A physically occupied account lane remains active even after logical cancellation or supersession. Batch Processing owns cancel controls, suggestions and human questions; session history never manufactures command authority.

## Capture grouped workspace

`MediaWorkspace` composes three evidence entry actions above named groups and ungrouped originals. `useEvidenceWorkspace` owns the accepted media projection, exact selected IDs/revision and one payload-bound retained command. Polling cannot replace dirty group/evidence editors or membership selections; confirmed receipts cannot be rolled back by an older read. Crop polling may update derived output while the original crop intent stays pinned.

`EvidenceDragContext` uses exactly pinned dnd-kit React/DOM adapters; pointer, keyboard and touch dispatch the same atomic `move_many` command as explicit selection controls. A conflict preserves selection until explicit reconciliation. Rename, evidence notes and group instruction editors keep loaded revisions and explicit save/discard. Review/viewer renders retained note provenance beside the same linked evidence identities. Grouping does not choose subject links or attachments.

`MediaUpload` keeps original File/revision/key outside form state. Photo and PDF controls bind their intended group before the picker opens. Original acknowledgement completes before a fresh membership read and separate move command; failed membership leaves the retained original selected in its confirmed ungrouped projection. A failed post-acknowledgement read is reported separately and never authorizes another upload. Media, settings and instruction drafts share navigation protection without allowing a clean sibling to clear it.

## Persistent header observations

The Masthead lives within the existing keyed server scope and LiveUpdates lifetime, above the application content. Ordinary batch-tab navigation preserves that header, the query subscriptions and dirty form nodes. `HeaderStatus` uses the generated public `headerClient` and scoped TanStack Query keys; response identity is checked against actor/target/context before publication. Connection reads poll every 30 seconds independently of healthy sockets; work reads keep the existing fallback cadence or a 30-second live safety poll. A local clock and foreground/visibility reconciliation enforce 60-second observation expiry.

`LiveUpdates` exports read-only transport state/time/coverage; no second socket is created. Transport freshness also expires locally under the shared 30-second last-frame policy, so foreground rendering cannot wait for a background-throttled socket deadline to report stale/unknown health. API read success, live transport and target reachability remain independent. Fresh failed target probes are unavailable; stale/unobserved observations cannot display reachable. Only validated same-context HTTP(S) root navigation with no credentials/query/fragment becomes the isolated Open InvenTree link. Header navigation does not change the dirty guard or grant command authority.

The controlled Radix disclosures are mutually exclusive, portalled outside the decorative header and bounded/scrollable at narrow widths and native zoom. Workflow details prefer current-batch work, retain known steps with incomplete coverage, distinguish selected from reported model identity and show physical occupancy despite logical cancellation. No-active-agents requires fresh complete coverage and a free lane. The former global activity strip is retired; Processing/Results/Agents navigation remains in the disclosure and page-level diagnostics remain. No header mutation controls or inferred completion percentages are added.
