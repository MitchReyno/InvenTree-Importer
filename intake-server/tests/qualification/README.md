# Retained photo workload

Run `pnpm --filter @invimport/intake-server exec tsx tests/qualification/media-load.ts PROFILE` with a disposable PostgreSQL server, the immutable decoder image and the local Docker engine socket. The database helper requires `INTAKE_TEST_ADMIN_URL` and `INTAKE_TEST_ALLOW_CREATE_DATABASE=owned-sandbox`. Set `INTAKE_MEDIA_DECODER_IMAGE` to the output of the repository image build and `INTAKE_BENCH_ENGINE_SOCKET` to the Unix socket of the Docker context used by the decoder.

Each invocation uses a fresh database, restricted four-connection API and decoder roles, a private dispatcher socket and synthetic photos. Twelve ordered uploads contain six 2400 × 1600 images twice, alternating normal and rotated orientation. One older page is missing its renditions and has a pending figure. Four Capture reads, one HTTP liveness read and a scoped status observation are offered every 300 ms. The driver bounds outstanding groups and reports missed groups when the offered load exceeds capacity. Preview visibility is sampled independently every 50 ms.

Use a clean checkout of the pre-drain implementation with the pinned workspace packages installed for `INTAKE_BENCH_BASELINE_ROOT`. The `original` profile runs that checkout's worker step and pause policy at one slot. The other profiles run the current supervised worker. Use `shared` for one decoder and four shared database connections, `one` for one decoder and three ordinary connections plus one for health, and `two` for two decoders at that same allocation. The `adverse` profile occupies the ordinary pool, fails the synthetic target, and observes its recovery.

Warm the decoder first. Rotate the profile order across five paired trials on an otherwise idle machine. Compare median time from the first upload to the last visible preview and the ordinary-request p95 against the better one-slot implementation. Inspect the interval after final upload separately. Compare preview and rendition digests across all trials. The whole-workload duration also includes the figure and the backfill. Queue and preparation intervals use PostgreSQL timestamps. A deferred trigger in the disposable database samples the duration of each publication transaction immediately before commit. Decode durations use the launcher's monotonic clock. The engine sampler observes only named test containers. Its samples are lower bounds on child peaks and CPU use. Report these with the process RSS high-water mark and the hard per-container memory and CPU limits.
