# Testing the intake foundation

Read the shared [testing rules](../CODE_GUIDELINES.md#testing-and-tools) and [implemented architecture](ARCHITECTURE.md) first. This file specializes those rules for the public HTTP, database, target-transport and durable-runtime seams; it is not a second general style policy. Commands run from repository root with the pinned Node/pnpm versions and a frozen install. Never load root `.env`, copy real inventory credentials or contact the protected inventory endpoint for a test, including a supposedly refused-write probe.

## Distinct test tiers

| Tier                          | Command                                            | Required environment and assertion boundary                                                                                                                                                                                                                                              |
| ----------------------------- | -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Fast contracts/HTTP/transport | `pnpm test:intake`                                 | No DB, Docker, key or inventory service. Real HTTP parser/serializer and ephemeral owned HTTP endpoints, plus explicitly injected bootstrap settings. Fixture echo/CSRF routes are test-only and never application routes                                                                |
| Generation and types          | `pnpm contracts:check` and `pnpm typecheck:intake` | Reproducible artifacts and TS consumer compatibility; not evidence of runtime validation or inventory authorization                                                                                                                                                                      |
| Real PostgreSQL               | `pnpm db:intake test`                              | Reuses the ledger-owned local PG, creates/drops randomized test databases. Exercises reviewed migrations, constraints, transactions, grants, exact driver scalars/bytes and lock conflicts                                                                                               |
| Real worker process           | `pnpm db:intake test:process`                      | Same isolated database setup; actual pinned DBOS public API, killed/reaped child, version rejection and recovery. Includes bounded DBOS qualification plus T03/T04 supervised persistent-fake effects, ownership, ACK-loss and restart cases; no actual InvenTree mutation qualification |

CI and explicit service allocations use `pnpm --filter @invimport/intake-server test:pg` / `test:process` with `INTAKE_TEST_ADMIN_URL` naming a loopback `/postgres` database and `INTAKE_TEST_ALLOW_CREATE_DATABASE=owned-sandbox`. They must fail loudly if required configuration/services are absent. The fast suite deliberately does not run them: that separation is not a skip or passing PG qualification. If a future opt-in check can skip, report its skip and unresolved capability explicitly; do not silently select another DB or reinterpret an unavailable service as success. No suite auto-loads dotenv. See the [service ledger](README.md#shared-development-service-ledger) before allocation/restart experiments.

## Cases that discriminate between plausible implementations

- Exercise actual HTTP bytes for parsing and output serialization, not only `validate()` on an already-parsed object. Equal duplicate values, decoded/escaped duplicate keys, invalid UTF-8, oversized and over-deep bodies catch parser mistakes hidden by `JSON.parse` or injection-only tests. Keep nearby valid controls so rejecting everything cannot pass. Output validation must fail closed on extra private fields rather than silently strip them.
- Use distinct actor/target/context/observation IDs, differing digests and revisions above JavaScript's safe integer range. Wrong-model Part/location references and nested extra properties must fail. Test missing versus explicit clear versus inherit, duplicate selected IDs and contradictory worker discriminants. Boundary quantity controls include `0.000001`, `9999999999999.999999`, excess precision, zero and exponents; strings must survive HTTP and PG unchanged. Do not compute expected values by calling the serializer or arithmetic being tested.
- Retain independent exact expected UTF-8 hex/SHA-256 vectors, including asymmetric Unicode and ordered arrays. Check both bytes and digest after PG round-trip; JSONB or a recomputed hash alone is not original-byte authority. Sort schema-defined sets deliberately, never human text/ordered arrays indiscriminately.
- Test the repository's public transaction seam against real PG, including a domain row and dedup result committing/rolling back together, concurrent identical requests and changed-payload conflicts after restart/reconnection where implemented. A callback counter alone is not durable idempotency evidence. SQL fixtures for future composite/cyclic ownership must be labeled representative, not implemented catalogue tables.
- Verify lock ordering through a competing transaction and PG's lock timeout/error code, not an arbitrary sleep followed by a boolean. Verify rollback restores the stream head and event count. Retain transaction-boundary and privilege assertions, not private helper call order or generated SQL spelling.
- For protected-target refusal, assert both zero injected transport invocations and zero hits on a controlled endpoint configured as protected. Separately assert independent actual method/path/body and exact counts on an allowed disposable endpoint. Redirects must not reach their controlled sink. Never substitute the protected real URL, even to prove a guard works.
- Process tests must observe a durable checkpoint before killing, reap the child before recovery, and check retained workflow identity/full inputs and actual executing-handler version. Bound polling and clean up owned children in `finally`. An observed scheduler restart is not proof of physical writer ownership, lost remote ACK recovery, cross-host exclusion or all future interleavings. T03 must add those at the actual apply seam.

## T01 self-assessment and applied improvements

The first T01 tests used too many identical IDs, mostly successful echo examples, a callback count for idempotency, a sleep-based event lock assertion and endpoint counts without proving refusal before the transport adapter. Those could miss swapped bindings, equal-duplicate JSON acceptance, durable rollback errors, timing races and unnecessary forbidden transport calls. The revised tests use asymmetric fixture identities/digests, real-byte adversarial HTTP with nearby valid controls, independent wire observations, persisted business/dedup rows, and a deterministic competing PG transaction returning `55P03`. An oversized-body case initially exposed a real parser installation bug (400 instead of 413); the shared parser now sets its own 256 KiB limit rather than relying on the surrounding Fastify instance.

The focused `HTTP adversarial` test was run unchanged against a temporary mutation disabling duplicate-key rejection. It failed on the equal-duplicate request with HTTP 200 instead of 400. Restoring the exact parser line made that same test pass; the parser's before/after SHA-256 was identical. No mutation remains. The [T01 handover](../docs/handovers/bench-intake-T01.md) records commands/results and retained local evidence. This negative control proves that particular regression is detected, not mutation-score completeness.

Remaining T01 test limits were deliberate and owned: no real inventory service writes/requests, no browser capture UI at that stage, no lost *app database* commit ACK/process qualification for idempotency, no production grant/permission discovery, no physical apply owner, and no InvenTree sandbox HTTP qualification. The DBOS crash fixture simulates scheduler commit before outbox ACK and uses a real kill/recovery only for its synthetic worker. Extend the same public seams when those features exist instead of claiming these tests qualify them now.

## T02 capture scenarios and self-assessment

`tests/pg/capture.test.ts` exercises actual loopback HTTP with a restricted random PG role, not `inject()` alone: two distinct original contributions sharing one Part; minimum/maximum exact quantities; PK above safe-integer range; default location 104 → 105 with explicit override 108 unchanged; omitted/clear/unknown/unset/inherit history; concurrent saves expecting exactly 200 + 412; malformed scalars; foreign batch/model/context/observation references; retained immutable source/note/selection/command bytes; archive/resume and reconnect. `capture-process.test.ts` restarts actual `main.ts` against the same random DB, compares complete snapshots independently, proves one exact fake GET `/api/part/93/` and rejects the old CSRF token. No root environment or actual inventory is consulted.

The unchanged concurrency test was run with only the expected-revision guard temporarily disabled. It failed with actual `[200,200]` versus literal expected `[200,412]`; restoring that guard made the same PG suite pass. No mutation remains. This discriminates silent last-write-wins, not every concurrency interleaving. Fast read tests include mismatched/unsafe PK, duplicate JSON keys, excess bytes, denial/404 and a nearby safe numeric-ID control. Static qualification covers actual serving, parent/hidden-file refusal and Host protection with both wildcard and patched-glob registration; real browser evidence additionally exercises the built UI through actual `main.ts`.

The first browser narrow layout used a scrolling lot strip that partially hid the override, and expanded every historical note before the editor. Inspected screenshots identified both. The final narrow flow uses a full-width list → focused subject, explicit back action and latest human note plus accessible earlier immutable notes, preserving all history without a giant form stack. Component tests cover exact values/provenance/conflict/archive, not CSS/device proof. Actual desktop/390px/narrow/conflict/archive/list/restart screenshots and DOM/AX checks belong to the [T02 handover](../docs/handovers/bench-intake-T02.md). Compare against the [primary original reference](../docs/bench-intake/reference/README.md), preserving the user-approved light/blue palette, not the derivative board alone.

For manual rendering use `tests/fixtures/capture-browser.ts` only with explicit owned-sandbox test configuration: it creates a random DB/restricted role, controlled fake read endpoint and actual web child on reserved 4310. `SIGUSR2` restarts only that owned web child; `SIGTERM` reaps the child and releases its fake/DB/role. The fixture never restarts/drops the shared PG or shared `intake_dev`. Obtain private test configuration through the documented service workflow without logging credentials. Do not expose admin credentials to the browser or start another full stack. Current limits remain: no real inventory compatibility/permissions, no uploads/providers/apply/approval, no production identity, no lost app-commit ACK qualification and no full accessibility audit. T04/T11/T12 own those later gates.

## T04 manual journey and adverse cases

`tests/pg/manual.test.ts` uses actual loopback HTTP and restricted roles. It checks selected A only, exact literal quantity/location/barcode POST, restart/adoption, later B, and no replacement after deleting A’s fake stock. Independent read intents/results, review/index bindings, cumulative history, cursor consistency, immutable bytes, exact batch/stream parents and temporary-schema shadows are checked at PG boundaries.

Unavailable reads and shared edits while reads are in flight produce no executable plan. Duplicate preparation approval adopts the original authority after a later draft edit, while changed semantic payload conflicts. Unknown A blocks B; cancellation and proven no-effect recovery retain the original run. Missing preparation indexes/read receipts and altered preview labels/excluded scope/outcome bytes are privileged faults in random disposable DBs; runtime roles cannot perform that corruption. A resumed already-claimed dispatch produces zero POSTs and requires inspection, rather than silently relaunching a writer.

`tests/process/manual.test.ts` starts actual `main.ts`, explicit DBOS runner and supervised physical child against the persistent fake. It covers approval committed before enqueue, web/fake/runner restart, exact later-round POST counts, real TCP domain-approval COMMIT-ACK loss, and dedicated-writer connection loss before a create followed by original-run recovery. No generic retry or uncertain-COMMIT retry is added. Existing T03 intent/result-loss, surviving physical child, HTTP421 one-send and restore-witness tests remain applicable.

The selected-scope negative control temporarily included every lot in a requested A-only closure. The unchanged regression failed at the literal selected IDs; the original model bytes were restored and the full PG tier passed. This proves detection of that scope leak, not exhaustive concurrency qualification.

`tests/fixtures/manual-browser.ts` is explicit owned qualification only. Its separate 4330 preview preserves the T02 4310 fixture and uses the sole shared PG. Browser-harness desktop/narrow evidence and independent safe receipt summaries are linked in the [T04 handover](../docs/handovers/bench-intake-T04.md). Recordings remain disabled. Component tests validate emitted commands and stale/unknown UI, while actual browser checks validate layout and the integrated journey; neither substitutes for production access or a full accessibility audit.

## Live and operations boundaries

`tests/pg/live.test.ts` uses real WebSocket upgrades and PostgreSQL commits, including uncommitted events, exact cursors above 2^53, reset/refusal and scoped reads. `tests/live-frames.test.ts` checks the slow-peer send bound without claiming a real network saturation test. `tests/pg/operations.test.ts` invokes the owned PostgreSQL17 dump/restore binaries, verifies retained byte identity and exercises corruption/active-gate/separate-scheduler/existing-destination refusals. Its native-tool adapter forwards only synthetic PG settings into the existing container and never starts another database.

`tests/process/operations.test.ts` starts actual web/DBOS/apply processes, observes live completion and restores a coherent backup older than a later fake remote create. Both disabled activation and preserved external witnesses prevent another POST; reactivation occurs only as an explicit adverse action in this isolated fixture. An open WebSocket is reaped during web shutdown and incompatible migration startup produces only redacted event codes. Frontend live tests count idle reads, preserve local input across invalidations/reconnect and reject regressing frames. Browser request-count and layout evidence belongs to the T10 task record; tests never use the original environment file or real inventory/providers.
