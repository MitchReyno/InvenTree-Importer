# Implemented intake application

T01 adds the Fastify/TypeScript foundation and `contracts`; T02 connects the React browser to retained manual capture. Merged T03 adds a separately supervised fake-only stock executor through internal seams, not browser approval routes. No component calls Python, and capture grants no inventory-write authorization. [The approved implementation plan](../docs/bench-intake/08-implementation-plan.md) remains authoritative for later work; [T01](../docs/handovers/bench-intake-T01.md) and [T02](../docs/handovers/bench-intake-T02.md) handovers distinguish observations from fixtures.

## Public boundaries and process ownership

`api/server.ts` constructs an API without connections or workers. `main.ts` is the explicit loopback web entry point with signal-driven close, optional explicitly configured capture DB/read target and built same-origin static frontend. `registerCapture` is an additive registration seam; constructing the base server still installs only health/bootstrap. The strict parser validates UTF-8, depth/size, duplicate decoded keys (including equal duplicate values), finite/safe numbers and ordinary JSON syntax before object parsing. AJV Draft 2020-12 performs no coercion/default injection/stripping. Complete outputs are validated before serialization, so an accidental private field fails instead of being silently exposed. Safe error DTOs suppress original messages/bodies. Host/Origin and CSRF checks are independent of domain authorization; they cannot grant mutation capability or substitute for T11 identity/access qualification.

`config.ts` accepts explicit injected settings and stable development actor/target/context IDs. No module discovers `.env`, logs a key, falls back to username/password, contacts inventory or launches a process on import. The key is not a verified user identity. Web bootstrap does not claim target capability/permission verification. The protected root `.env` is outside T01's runtime configuration and was not read. Actual configuration-file/credential resolution and trusted actor/target persistence must be added with consuming features, not inferred from a successful health response.

## Manual capture boundary

`capture/routes.ts` installs GET list/read and POST create/edit/observation endpoints under `/api/v1/batches`. All lookups bind server-configured development actor plus fixed target/context. Commands require CSRF/Origin and payload-bound UUID idempotency; no browser-selected actor, origin, credential or raw inventory action exists. `capture/repository.ts` uses caller-owned transactions, batch row locks and expected revision comparisons (412, never silent overwrite). Read snapshots and stream cursors share a repeatable-read transaction. Observation creation is independent from explicit human selection and does not change field selections.

`migrations/0002_capture.sql` adds source, batch, typed subject/Part/lot, immutable human note, observation, selection and exact canonical command-history tables without changing 0001. Every physical lot retains its original source/contribution identity. Composite same-batch FKs and a deferred typed-extension constraint prevent cross-batch/type ownership. Notes/selections/observations/revisions are append-only through triggers and restricted capture grants; explicit selection commands retain old values and Part-link edits in original command bytes plus digest. No stock record or execution ownership is created by capture. Archive is reversible, not deletion or identity replacement.

The public snapshot keeps exact quantity/PK/revision strings and unset/unknown/clear/inherit/set modes. Omitted edit fields insert no selection revision; defaults cannot inherit themselves. Explicit choices/unknowns/clears survive default changes; inherited fields materialize in the browser projection without rewriting original selections. Capture currently bounds 100 subjects, 100 read observations and 240 KiB complete snapshots; excess edits roll back rather than retain an unreadable batch. Lists return at most the most recent 100 with explicit truncation; old direct URLs remain resumable. Large-batch pagination/bulk/restructuring belongs to later work.

`capture/read.ts` accepts only the existing transport's semantic read closure, never a write closure. It verifies returned PK/name, strict bounded JSON, 64 KiB and five-second total body deadline; denied/malformed/timeout is unavailable, not absent. Authorization precedes network traffic. `scripts/capture-setup.cjs` explicitly provisions development attribution/grants only in an allocated DB with trusted configuration; startup never migrates/provisions. T02 uses randomized owned test DBs/restricted roles, not shared `intake_dev` or real inventory. Merged T03's independent migration 0003/executor does not depend on capture SQL; T04 must integrate the public seams and retained lineage rather than couple their SQL internals.

`inventory/transport.ts` is a target/context-bound transport guard, **not** approval/request-intent authority. Semantic reads are `get_part(pk)`, `get_location(pk)` and executor known-output `get_stock(pk)`; raw URLs/actions are not accepted. Writes require an explicit owned-disposable profile, a nonempty protected-host deny set and a literal loopback HTTP origin. DNS names, public/LAN origins, binding changes, protected aliases and redirected requests cannot pass. The protected loopback spelling/IPv6/localhost group is conservatively denied across ports. Literal-loopback writes prevent public DNS rebinding; there is no general configurable remote-write route. NodeHTTP makes at most one request with a five-second header/connection deadline and no retry/redirect algorithm. T03 replaced native Fetch after a controlled HTTP421 test observed it repeating POST. T02 bounds read bodies; T03 retains stock intents/results and interprets supported output receipts. No broad read pagination or arbitrary request API exists. The apply process alone may receive a writable closure after it has independently authorized and committed its exact request intent; API/research must not receive one. Tests configure controlled endpoints as protected and prove zero forbidden sends; none target real inventory.

Protected-host classification uses WHATWG URL's validated canonical hostname, removes the terminal DNS dot and conservatively groups `localhost`, IPv4 127/8, IPv6 `::1` and IPv4-mapped IPv6 127/8 across ports. Mapped dotted/expanded forms normalize to IPv6 hex before classification. This does not resolve DNS or expand writable destinations: only HTTP `127.0.0.1` / `[::1]` remain eligible, and any protected loopback group denies both. Nearby non-loopback 126/128 addresses and `localhost.invalid` remain distinct; controlled public-seam tests prove both refusal before adapter/endpoint and allowed disposable positive controls. Independent review found the earlier exact-spelling classifier incomplete; the T01 handover retains the failing-before/passing-after evidence rather than claiming the original tests covered these aliases.

## PostgreSQL and exact authority

`migrations/0001_foundation.sql` owns explicit constraints/triggers and is reviewed as SQL, not generated schema push. It implements development operator, target/context, immutable command, outbox, semantic idempotency and UI-stream/event infrastructure. Target/current-context cycles are deferred composite FKs; wrong-target contexts, missing parents and bad digest lengths fail. Retained command/context/idempotency/event authority is append-only through triggers plus runtime grants; migration/DBA DDL remains trusted. Capture is additive in 0002. Merged 0003 adds independently owned executor deployment/source/approval/run/operation/request/result/effect/verification authority; processing catalogue tables remain future work. Same-batch/wrong-job ownership in T01 tests is a **test-only representative DDL fixture**, not an implementation claim for future job tables.

`db/schema.ts` supplies reviewed Drizzle row declarations and inferred types for the implemented access paths. `pg` retains `bigint`/numeric text by default; Drizzle bigint mode is `bigint`, never JavaScript number. Public DTOs use canonical exact decimal/revision/PK/cursor strings with field-specific bounds. Stock quantity supports 13 integer/6 fractional digits, positive and no exponent/sign/leading zero/trailing fractional zeros; schema validation precedes any numeric insertion. The real-PG numeric fixture proves no boundary-rounded value is inserted. UTF-8 canonical documents sort keys by JavaScript code-unit order, preserve ordered arrays/human text, allow string/boolean/null scalars and reject number/undefined/custom objects. Callers must explicitly sort schema-defined set arrays before canonicalization. Retained bytes plus SHA-256, never JSONB reserialization, remain authority; one cross-language Unicode byte/hash vector is retained under `contracts/vectors`.

`db/authority.ts` exposes payload-bound idempotency inside the caller-owned transaction, byte verification and commit-ordered event allocation. Idempotency serializes absent as well as present keys using a transaction advisory lock; exact canonical bytes are compared as well as their digest. Different property order is equivalent; changed semantic payload conflicts. Domain writes and dedup result must commit together. A lost commit acknowledgement is **not automatically retried**; consuming features must inspect stable keys read-only and retain uncertainty. No network call belongs inside a retried database transaction.

The global order is idempotency scope → target head → source guard → batch → subject/current heads sorted by ID → job/attempt/question → run/operation/request → stream heads sorted by ID. Skip absent domains, never acquire earlier domains after later locks. `appendEvent` holds the stream-head row lock until the caller commits/rolls back; an unrelated transaction cannot publish a later sequence first. Consistent future snapshots require one repeatable-read view of state and stream head. T02 owns capture migrations/repositories; T03 owns source guards/execution tables and dedicated writer-lock connection; they must coordinate migration IDs and shared contracts rather than query each other's SQL internals. No distributed writer, advisory-lock-only failover or automatic uncertain-write retry is enabled.

## Durable-runtime qualification boundary

DBOS SDK 5.4.0 is retained after actual PostgreSQL/process qualification. `workers/delivery.ts` performs **one** bounded public-client enqueue/inspection/ACK; it does not run a daemon, implement claims/leases or own inventory effects. Actual function/class/config, queue, application version and full input arguments must agree before ACK. Name collisions thrown by DBOS are classified through public retained state, not exception text/private tables. Changed payload/version/name/queue leaves a durable outbox conflict; it is removed from the eligible partial index. A missing/corrupt command fails before enqueue. The outbox ACK may be redelivered after scheduler commit loss, adopting one exact workflow identity.

The process test is synthetic bounded work: explicit launch, public durable event/message checkpoint, SIGKILL and proven exit, wrong-version non-recovery, executing-worker actual-version refusal, then same-version recovery and one workflow result. No undocumented DBOS tables are queried or mutated. Scheduler recovery is **not physical writer ownership**. T03 separately qualifies supervised apply, host exclusion, retained original-run uncertainty, cancellation and external epoch/restore gates against an owned persistent fake; see its [module architecture](src/execution/ARCHITECTURE.md) and [handover](../docs/handovers/bench-intake-T03.md). T04's current-draft/review/approval integration and T06's research attempt authorization remain future work. Do not turn DBOS auto-recovery into an inventory retry. No custom durable-runtime alternative was needed.
