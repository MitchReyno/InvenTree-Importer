# Intake server code guidelines

Follow the [shared guidelines](../CODE_GUIDELINES.md), [implemented architecture](ARCHITECTURE.md) and [testing tiers](TESTING.md). These rules apply to server TypeScript and its tests; they do not authorize inventory effects or change supported capabilities.

- Keep boundary validation, domain decisions, PostgreSQL persistence and external transport in their owning modules. Let a transaction read as explicit ordered steps with named results. Do not hide authorization, lock acquisition, committed intent, send or checkpoint ordering in compressed callbacks or generic retry helpers.
- Write one statement and variable declaration per line, use braces for branches and give compound certainty/ownership checks meaningful intermediate names. Avoid nested ternaries and dense boolean chains whose individual refusal conditions cannot be explained locally. A named predicate should describe the domain rule and retain all its inputs.
- Separate awaited query results from row selection and projection when combining them obscures behavior. Use descriptive row/operation names rather than single-letter bindings across substantial scopes. Format SQL template literals with visible SELECT/FROM/WHERE or INSERT clauses and keep parameter ordering easy to compare with placeholders. Existing immutable migration bytes remain unchanged.
- Extract operations at meaningful boundaries, such as reading retained authority, validating prior attempts or building a snapshot; keep cohesive checks together when splitting would obscure the invariant. Do not split by arbitrary file/function quotas or replace explicit effect sequencing with a framework.
- Apply `pnpm format` and inspect the resulting code before review. Prettier expands types, statement blocks and argument lists, but does not split comma declarations, add branch braces, explain complex predicates or reformat SQL strings. Those are author/reviewer responsibilities. Test fixtures should make setup, action and independently expected effects easy to distinguish too.
- For server behavior changes run the applicable typecheck, contract/fast and PostgreSQL/process checks from [TESTING.md](TESTING.md). Formatting-only changes require formatter stability, generated-byte checks, typechecking and the affected tests; selected hosted CI remains part of merge evidence. Preserve protected-target guards, retained identities/bytes and no-retry behavior during conflict resolution.
