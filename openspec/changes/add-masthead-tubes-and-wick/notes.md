- 2026-11-12T01:59Z — Review round 1 (head 24a995ab) found that the pointer nudge ran after the length constraints, stretching the ribbon by up to about 2.4× on a flick. The nudge now runs inside `stepRope` before the constraints, capped at half a segment per point per step. A final follow-the-leader pass holds each segment at its exact length, because 30 relaxation passes alone still let a sustained fast flick stretch it by about 4%. Round 1 also corrected the docs' "0 seconds settles it straight" claim (only a new rope hangs straight) and found that the scene lifecycle test lives in `scene.test.ts`, not a separate `scene-hanging.test.ts` as planned. It added a rim-anchoring assertion that fails if loose ends update before parts are placed (mutation-checked).
- 2026-11-12T02:07Z — Review round 2 (head e9f688b3) found that the rope's motion depended on frame rate. The step is now time-corrected Verlet: last step's movement is rescaled by `dt / previous dt`, damping is per second (0.9/s, about the old 60 Hz feel), and a 0-second step adds no motion. Tests that mutation-checked against the old code cover decay at 60 vs 120 fps and the ratio. The scene tests now spy on each loose end's own geometry, because the earlier disposal count passed without any ribbon released. They also start a reduced-motion scene to check the still frame. The wick builder's scratch vectors became per-instance, and the attribute casts were removed.
- 2026-11-12T02:15Z — Review round 3 (head 78cb2d1e) found that a recycled part was rendered once unposed and then turned to its random yaw. That moved a wick's rim by up to about 3 units in one frame and whipped the loose end for seconds. `recycle` now poses the replacement straight away. A scene test checks a recycled wick's end one frame after entry and is mutation-checked. The scene tests' `runFrames` clock now persists across calls, so single-frame stepping simulates 16.7 ms frames. Also: the damping constant became `DAMPING_RATE_PER_SECOND`, and the clear glass opacity is shared as `CLEAR_GLASS_OPACITY`.
- 2026-11-12T02:25Z — Review round 4 (head 76263865) found that the pointer nudge still depended on frame rate. It shifted positions without updating Verlet's `previous`, so each frame in range added another kick, and a hovering pointer could hold the end out at 72–84°. The nudge is now a velocity change like `applyStir`: a drag along with the pointer's motion, a push away, and a cap in units/s. Mutation-checked tests compare a 35 px hover at 60 and 120 fps and bound the hover tilt. New wick and scene tests check that the pointer reaches the loose end; the scene test is mutation-checked against a scene that never passes the pointer.
- 2026-11-12T02:30Z — Review round 5 (head 38fe0d56) found that the speed cap clamped a point's whole velocity, so a faint nudge braked a fast-moving rope. The cap now never goes below the point's existing speed, and a test, mutation-checked against the old cap, covers it. The docs now describe the drag as following the pointer's motion.
