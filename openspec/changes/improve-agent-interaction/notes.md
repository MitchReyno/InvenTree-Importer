# Implementation notes

Implementation of BI-019's agent interaction work, delivered PR by PR as the tasks' delivery map sets out. PR-B delivers tasks 2–4 (stepped `/2` questions and answers). The other PR bundles add their own entries. PR-A delivers task 1 (dialogs close from their backdrop). PR-D1 (task 5) records photo views and agent-reported web page sources. PR-D2 (task 6) adds the paged history read and the photo-view crop route.

## Changes to the plan

- **2026-11-24T10:39+11:00, task 6 (PR-D2):** Lot entries can't say why a lot is separate: `propose_lot` records no separation reason, so lot details list `separation_reason` under `not_retained`, as the design's "where a detail isn't retained, the entry says so" allows. Showing the reason needs `propose_lot` to take one; that is a follow-up, not part of this change.
- **2026-11-24T10:39+11:00, task 6 (PR-D2):** Failures have no entries of their own. Each attempt header in the metadata carries its failure, since a failure can arrive with no inbox or outbox item, so the entry kinds are the design's list without `failure`; the drawer and page show a failure from its attempt header.
- **2026-11-23T18:24+11:00, task 4 (PR-B):** Every session drawer now answers its questions in place, not only Inventory's, because the processing-workspace delta says "A session drawer SHALL answer a session question in place" and the Inventory requirement says options answer "as in every session drawer". A question pinned on its step page is still answered there and linked from the drawer. The frontend architecture is updated.
- **2026-11-23T18:24+11:00, task 3 (PR-B):** The synthetic session asks a two-step question about the lot's count (a number, then how it is packed) with fields `quantity` only, so the "Unclear quantity" pipeline test keeps the identity current. The fake CLI's `ask-steps` mode asks the three-step choice, number and choice question the process test answers.
- **2026-11-23T19:18+11:00, task 1 (PR-A):** Mitch decided to build dialogs on `@radix-ui/react-dialog` 1.3.1 instead of the hand-rolled backdrop handler, after four review rounds of pointer and click edge cases left one open (two pointers releasing before the first click). `Dialog` and the crop editor now share one Radix layer (`ModalFrame`), and `useBackdropClick.ts` and its geometry tests are gone; the entries below about that handler are history. The proposal, design and task 1 are updated; the spec's behaviour is unchanged. Radix Dialog is the change's only new dependency.
- **2026-11-23T17:56+11:00, task 1 (PR-A):** Review showed two gaps in the design's handler, which recorded one press and checked both points on `click`: a second pointer could arm another pointer's release, and a browser may round `click` coordinates across a fractional edge. The handler now tracks each pointer's press, checks the release on `pointerup`, and checks only the target on `click`. The box's right and bottom edges count as outside, matching Chromium's native hit test. The ui-design-system requirement now promises Esc parity only where Esc closes the dialog, and a scenario covers the crop editor, which ignores Esc and keeps a sending or unconfirmed request open, as the design's "own close guard" implied. design.md and the spec delta are updated.

## Unexpected challenges

- **2026-11-24T10:39+11:00, task 6 (PR-D2):** The PG tests were written in the same pass as the read rather than strictly first. Mutations confirmed they fail without the behaviour: dropping the attempt from the cursor's order fails the paging test, and not publishing from `read_inbox` fails the inputs test.
- **2026-11-24T09:15+11:00, task 5 (PR-D1), merging #256:** `polish-ui-styling-and-loading` took migration `0035` for agent settings save receipts, so the photo-view migration is now `0036_session_photo_views.sql`. The two are independent: `0036` only widens the outbox `kind` check from `0018`. A database that applied the earlier `0035_session_photo_views.sql` keeps that ledger entry, so the exact migration check refuses to start against it; such databases were only owned, disposable test databases, and verification uses fresh ones.
- **2026-11-24T02:40+11:00, task 1 (PR-A), merging PR-B:** Radix labels its dialog only on a later render, once its Title has registered, so on a remount the drawer's first Effects found no heading and PR-B's move of focus to the drawer heading did nothing. `Dialog` now gives its title an id and passes it to `ModalFrame` as `labelledBy`, so the dialog is labelled from its first render; the crop editor keeps Radix's own label. PR-B's drawer tests that read Needs you behind the open drawer now query it as hidden.
- **2026-11-23T17:35+11:00, PR-B:** A worktree with `node_modules` symlinked from the main checkout resolves `@invimport/contracts` to the main checkout's sources, so typecheck and tests silently ran against unchanged contracts, and root `pnpm` scripts refuse a symlinked root `node_modules`. The worktree uses its own `pnpm install --frozen-lockfile` instead; the lockfile is unchanged.
- **2026-11-23T21:13+11:00, task 1 (PR-A):** Radix renders `role="dialog"` without `aria-modal`, where `showModal()` exposed the dialog as modal to assistive technology. `ModalFrame` sets `aria-modal="true"` on the surface.
- **2026-11-23T20:39+11:00, task 1 (PR-A):** Radix's `aria-hidden` helper leaves live regions and their ancestors exposed, so masthead buttons that hold a live status stayed reachable behind a modal, where the native modal had made the whole page inert. `ModalFrame` now marks every other top-level element `inert` and `aria-hidden` while it is open (`ui/page-behind-modal.ts`) and removes only what it added, so a modal beneath keeps its own. Live regions behind a modal are therefore silent, as they were behind the native modal.
- **2026-11-23T20:17+11:00, task 1 (PR-A):** The native modal's browser stylesheet had capped the drawer short of the viewport, which left a strip of dimmed page beside it on phones. Without it, the Radix drawer covered a 390px screen and left nothing to click. The drawer is now capped at the viewport less a 32px gutter.
- **2026-11-23T19:18+11:00, task 1 (PR-A):** Radix autofocuses in an Effect of an ancestor of the dialog's content, after the content's own Effects, where `showModal()` had focused before them. The drawer read that later focus as the operator moving focus and skipped its move to the next question. `ModalFrame` now places initial focus on the first tabbable control as the surface mounts, so Radix finds focus inside and leaves it.
- **2026-11-23T19:18+11:00, task 1 (PR-A):** A Radix modal hides the page behind it with `aria-hidden` and blocks its pointer events, as a native modal made it inert in browsers; jsdom had not modelled that. Tests that read or clicked the page behind an open dialog now close it first, query with `hidden: true`, or, for the harness's stand-in for another tab, click with `fireEvent`. Tests that sent a native `cancel` event press Escape instead. `useReviewKeyboard` and `DrawerAnswers` looked for a `<dialog>` element and now use `OPEN_MODAL_SELECTOR`, since a Radix popover also has the dialog role.
- **2026-11-23T17:40+11:00, task 1 (PR-A):** Task 1.1's inventory of `Dialog` users is wider than the design lists: `RestructureDialog` and `CompareMatches` also use `Dialog`, besides `RemovalDialog`, `EvidenceGroupPanel` and the session drawer. They get the backdrop click with no change. `RemovalDialog`, `CompareMatches`, `RestructureDialog` and `EvidenceGroupPanel` set `closeDisabled` for pending or dirty work; the session drawer leaves it unset, and its `onClose` shows the save-or-discard banner instead. The component gallery fixture's dialog closes by clearing its open state. `MediaCropDialog` is still the only direct `DialogSurface` user.

## Decisions made during implementation

- **2026-11-24T10:39+11:00, task 6 (PR-D2):** Entry IDs are `outbox:<attempt>:<seq>` and `inbox:<seq>`; a web read adds `:web:<source index>` to its proposal's ID. The `before` cursor is the page's oldest row as base64url JSON (time to the millisecond, stream, attempt and sequence); the read refuses anything it can't parse as one with `invalid_history_cursor`. Rows order by creation time, then outbox before inbox, attempt and sequence, inbox rows sorting under a nil attempt ID.
- **2026-11-24T10:39+11:00, task 6 (PR-D2):** An attempt's reason for starting is `first` for attempt 1 and `after_failure` when the attempt before it failed or was interrupted, and null otherwise. No revise request is retained on an attempt or its input, so none is shown.
- **2026-11-24T11:20+11:00, task 6 (PR-D2), after review round 1:**
  - `propose_lot` now records what it did on its outbox item (`outcome`: `formed`, `extended` or `suggested`), since its first call can extend an existing lot or only suggest for an edited one. An item recorded before this has no outcome and reads "Proposed". Like regroups with `moves`, a `lot` item with an `outcome` can't be decoded by a build before PR-D2, so the rollout's forward-only note covers both. A regroup move already in its lot is recorded as `unchanged`, and the summary counts moved, suggested and unchanged moves apart.
  - The predecessor's reason is read from its last state before any supersession, so a Start fresh after an interruption still reads `after_failure`. An attempt's end is its latest transition by retained sequence, not by time, since a transition's time is its transaction's start.
  - The read returns every attempt, up to 1000, and refuses a longer lineage with `session_history_capacity` rather than cutting headers off older pages.
  - The read is scoped by any session attempt of the job in the caller's account, so a job whose stage was later queued under a profile without sessions keeps its history; `current_attempt_id` is then that attempt.
  - A proposal's note sources link to the note, a capture note with its subject or an evidence note with its evidence. An entry holds up to 1000 links, enough for 100 sources and every open question.
  - A web read goes with the first citing proposal in the attempt's outbox sequence.
- **2026-11-24T10:39+11:00, task 6 (PR-D2):** An instruction is labelled relayed when its inbox key names an attempt, as Start fresh and restarts key their copies. An evidence notice keyed `restored:` reads as a restored photo.
- **2026-11-24T10:39+11:00, task 6 (PR-D2):** Summaries are server-built lines of at most 300 code points. `web` in an attempt header is null unless its profile has web access, matching what `createSessionAttempt` seals. Questions that make a proposal provisional are read from any job of the batch, since the lead session's question about a lot makes that lot's Research proposal provisional.
- **2026-11-24T10:39+11:00, task 6 (PR-D2):** `proposalCurrentness` in `processing/read.ts` became `proposalCurrentnessFacts`, which returns the matching open question IDs, so the history and the Processing snapshot share one predicate.
- **2026-11-24T10:39+11:00, task 6 (PR-D2):** The photo-view crop route serves PNG resized to the delivered width and height. The OpenAPI browser-resource check accepts only PNG, WebP and octet-stream, and the delivered image was re-encoded anyway, so the route doesn't repeat its JPEG encoding. It is registered with the media routes, which hold the blob store and the private crop cache.
- **2026-11-24T10:39+11:00, task 6 (PR-D2):** `SessionHistoryEntry` is not registered as its own schema: the generated OpenAPI inlines every registered schema, and the entry inlined twice would have added 1.5 MB. `SessionHistory` adds about 0.8 MB to `openapi.json`.
- **2026-11-23T17:40+11:00, task 2 (PR-B):** Step and option IDs are agent-chosen slugs (`^[a-z0-9][a-z0-9_-]{0,39}$`), not UUIDs, so an agent can name them and read them back in its answer. The design left their format open.
- **2026-11-23T17:40+11:00, task 2 (PR-B):** The `/2` ask and the `/2` question DTO carry `schema_version: 'bench-intake-question/2'`, which discriminates them from `/1`; the session envelope stays `bench-intake-session/1` with a third payload variant. The `/1` DTO's `spec` no longer repeats `subject_id`, which every question now carries at the top level.
- **2026-11-23T17:40+11:00, task 2 (PR-B):** The attention item's question summary is structured (`question.steps[]` with kind, option count and assumption, null for a runner question), and the browser words it; `detail` keeps the first step's assumption.
- **2026-11-23T17:55+11:00, task 3 (PR-B):** No new profile or instruction digest is needed for the changed guidance. The `ask` schema is published only by `agents/tools/server.ts`, and the one-question sentence goes into `openingText`'s `instructions`, which are the opening user message, not the digest-checked profile instructions. Resumed sessions keep their earlier opening.
- **2026-11-23T17:55+11:00, task 3 (PR-B):** The note line separator is " — " (prompt — answer), one line per choice or text step and per number step answered in words, as planned. A note over the limit is refused naming the step whose line crosses it; an inbox payload over 32,768 bytes is refused without a step.
- **2026-11-23T18:24+11:00, task 4 (PR-B):** Picking an option only chooses it; Send (or "Send N answers" after the summary) sends. `OptionRow`'s escape option and option detail became optional so agent options without a detail, and choices without "Something else", use the same cards. The step progress is the "Step N of M" text without the canvas's progress segments, which PR-F reworks.
- **2026-11-23T19:10+11:00, tasks 2–4 (PR-B), after review round 1:** A one-step question is labelled by its prompt even when the agent gave a title, as the design's "a one-step question uses its prompt" says; the title labels only a question with several steps. A `/2` answer with no steps passes the contract so the stored question names the missing step as `invalid_answer`, matching a partial answer. Ask and answer text that PostgreSQL can't store (NUL or an unpaired surrogate) is refused before any write, naming its path or step. Text limits in the form count code points, as the contract does, rather than using a native `maxLength`.
- **2026-11-23T19:40+11:00, tasks 2–4 (PR-B), after review round 2:** A `/2` question's prompts, assumptions, title and option labels must hold a visible character, so a blank assumption is refused like a missing one. The answer note keeps one line per step: line breaks inside a prompt or answer become spaces there, while the session still receives the text as written. The Inventory comparison shows the question's kind or step count and its assumptions, as the other question readers do.
- **2026-11-23T20:05+11:00, tasks 2–4 (PR-B), after review round 3:** "A visible character" excludes whitespace, control and format characters (such as a zero-width space) and combining marks, checked by one contract pattern. The question card and option cards wrap a long unbroken word instead of clipping it.
- **2026-11-23T20:40+11:00, tasks 2–4 (PR-B), after review round 4:** Note lines treat every Unicode hard line break (LF, VT, FF, CR, NEL, LS and PS) as a break. Chat bubbles and Needs you rows wrap a long unbroken word. The pipeline's "Unclear quantity" scenario names the Examine lead as the asker, while the synthetic Research session asks the two-step count question used by `selective-rework`; a PG test now has the lead ask the one-step number question, with its estimate provisional, its identity current and Research still proposing, and the attention test reads that question's number row with its assumption.
- **2026-11-23T21:30+11:00, tasks 2–4 (PR-B), after review round 5:** The native-session qualification driver reads questions through `questionView`, so its chat evidence and report carry every step's prompt and assumption for either version; the script's other type errors against the current agents settings contract predate this change. Inventory cards, step-page question rows and job-card questions wrap a long unbroken word.
- **2026-11-23T22:20+11:00, task 3 (PR-B), after review round 6:** The capture lock's ordered edits accept a sequence of more than one edit only when each sets a lot's quantity alone or adds a note, since those change no archive state or subject list that a later edit in the same sequence is checked against; any other sequence is refused as `capture_edit_sequence_unsupported` before an edit applies.
- **2026-11-23T23:40+11:00, task 4 (PR-B), merging #250:** `polish-ui-styling-and-loading` moved and reworded `QuestionAnswer`'s consequence line to sit beside Submit. PR-B had split that form into `SingleAnswerForm` and `SteppedAnswerForm`, so both take the new line; the stepped form shows it only beside Send, not beside Next.
- **2026-11-23T21:03+11:00, task 1 (PR-A):** Per-element hold counts still let two modals opened in the same commit inert each other. `ui/page-behind-modal.ts` now keeps one stack of open modals, as the browser's top layer did: only the topmost surface and its backdrop stay live, it is un-hidden if a sibling opened in the same commit hid it, and isolation is recomputed whenever the stack changes, so closing in any order leaves the page inert until the last modal closes. It runs in a layout Effect, so the page is live again before content a closing owner mounts takes focus.
- **2026-11-23T20:48+11:00, task 1 (PR-A):** Stacked modals can close in any order: a refresh that moves the open file unmounts the evidence viewer while the crop editor over it stays open. `ui/page-behind-modal.ts` therefore counts holds per element and restores an element's own attributes only when no open modal still holds it. The ref-counted `inertOthers` in `aria-hidden` 1.2.6 (MIT, already installed for Radix) was rejected: its counter is one module-level map shared across attributes, and Radix's own `hideOthers` uses the same instance on the same nodes, so whichever undo runs first only decrements the shared count and the other attribute is left behind; with parent Effects cleaned up first, `inert` would stay on the page. With the whole page inert, a toast that appears behind a modal is covered too, so the separate open-modal count for toasts (`ui/open-modals.ts`) was removed.
- **2026-11-23T20:28+11:00, task 1 (PR-A):** Radix hides only page content present when a modal opens. A toast's action reads an open-modal count (`ui/open-modals.ts`, which `ModalFrame` registers with) and is `inert` and `aria-hidden` while any modal is open, so a toast that appears after the modal, such as a move confirmed while a viewer is open, has its Undo out of reach. A toast mounted inside the app's root already inherits the root's `aria-hidden`; the flag also holds for one rendered elsewhere and keeps Undo out of keyboard reach.
- **2026-11-23T20:07+11:00, task 1 (PR-A):** Focus on close tries the opener, then `returnFocus`, then the title of a modal still open beneath, and moves on when a target is gone or won't take focus. A disabled opener, such as the crop button after a confirmed crop whose follow-up read failed, would otherwise leave focus outside the evidence viewer still open behind it.
- **2026-11-23T19:32+11:00, task 1 (PR-A):** Safari does not focus a clicked button, so the focused element is not always a dialog's opener. `trackDialogOpeners`, started from `main.tsx`, records each click until the end of its task, and a dialog that opens during that click takes the clicked control as its opener; otherwise the focused element is. This settles the earlier open item about Safari focus return. Reading the deprecated `window.event` was rejected.
- **2026-11-23T19:18+11:00, task 1 (PR-A):** Dialogs take a new `z-dialog` token, since the native top layer is gone. It first sat below `z-popover` so a popover inside a dialog stayed above it, but then page toasts painted over an open modal. It now sits at 1200, above `z-toast` (1100), as the top layer did, and a popover opened inside a modal portals into the modal's surface through `ModalContainerContext`, so it stacks above it and stays in its focus scope. Giving popovers inside dialogs a higher layer instead was rejected: it needs a second popover token for the same component. `Toast` keeps its live region on the message alone, since the page-hiding helper leaves `aria-live` subtrees exposed and would otherwise expose Undo behind a modal. Focus returns from Radix's `onCloseAutoFocus`, just after the dialog unmounts, and only when focus was left on the page body, so an owner that focuses a result as it mounts, such as a confirmed delete's group, keeps it. Restoring focus synchronously on unmount was rejected: the focus trap is still listening then and pulls focus back into the closing dialog.
- **2026-11-23T17:40+11:00, task 1 (PR-A):** The design's "outside its content box" is read as outside the dialog's border box (`getBoundingClientRect`), since a press on the surface's padding must not count and the padding lies outside the content box. The check lives in `ui/useBackdropClick.ts`, which both `Dialog` and `MediaCropDialog` use.
- **2026-11-23T17:40+11:00, task 1 (PR-A):** `MediaCropDialog` ignores Esc, and its Discard and close button drops even an uncertain request. Its backdrop click uses the guard its native close already applies instead: an unsent or confirmed view closes, and the editor stays open while a request is sending or unconfirmed. Once the request or an exact retry is confirmed, a backdrop click closes it again. Following the Discard button was rejected because a stray click would drop an unconfirmed request's identity. The backdrop click closes the native modal first and lets the existing `close` handler tell the parent, so the browser returns focus to the opener; unmounting an open modal skips that.
- **2026-11-23T17:43+11:00, task 5 (PR-D1):** Readers of the outbox union are the session timeline read (`agents/tools/timeline.ts`), the status-line readers (`agents/tools/outbox.ts`, the session list and header), the reply lookup in `handlers.ts`, and the frontend `SessionTimeline` and `SessionChatPanel`; the last two filter by kind, so only the timeline needed a `photo_view` label, "Prepared a photo for the agent", since a view may exist for an image that was withheld. Readers of proposal sources are the `propose` handler's delivery and removal checks, the retained decoder (`processing/retained.ts`), the evidence-removal staling query (`processing/currentness.ts`, which matches only delivered kinds), `processing/stable-identity.ts`, Review's records projection (`contracts/src/records-projection.ts`, which reads a proposal's catalogue whatever its version and never its sources), and the frontend `ProcessingSources` (Examine, the job cards and Review's lot evidence). No Review or Inventory path counts a source as a receipt or verified evidence beyond these, so treating `web_page` as unverified meant keeping it out of every delivery and receipt check and labelling it agent-reported.
- **2026-11-23T17:43+11:00, task 5 (PR-D1):** A web page URL is checked twice: the contract's pattern (http(s) scheme in any case, no whitespace or control characters, no `@` in the authority, at most 2048 characters) and `webPageUrlAccepted`, which also requires the WHATWG parser to accept it with a host and no credentials. A custom AJV format was rejected because the tool's JSON Schema is advertised to provider CLIs, which may not know it. The handler reports a parser refusal as a `format` issue at `/proposal/sources/<n>/url`.
- **2026-11-23T17:43+11:00, task 5 (PR-D1):** The uncertain-outcome result is a new tool error code, `outcome_uncertain`. The final fetch transaction takes the batch row `FOR SHARE`, which conflicts with an evidence removal's `FOR UPDATE`, and then the job, attempt and session rows through the same check `withSession` uses (`requireRunningSession`). A metadata-only answer after encoding (an image too large at any quality, or an exhausted budget) goes through the same transaction but records no view; one that returns before encoding, with no blob store or no crop cache for a region, does not reach it.
- **2026-11-23T17:43+11:00, task 5 (PR-D1):** `photo_view` records the requested region as `{x, y, width, height}` in page-preview pixels, like the tool result's `delivered.region`; the preview size it refers to is the page's, so the crop route in task 6 can recut it.
- **2026-11-23T17:43+11:00, task 5 (PR-D1):** A `web_page` source shows outside debug mode as a "Web page" source chip in the warn style, certainty "Agent-reported", whose popover links the page (opened in a new tab, `noopener noreferrer`). The other source identities stay in the debug-only list. The URL limit counts code points, as JSON Schema's `maxLength` does.
