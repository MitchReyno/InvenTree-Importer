# Implementation notes

Tasks 1–14 were delivered after planning ([#94](https://github.com/MitchReyno/InvenTree-Importer/pull/94)) in seven PRs merged into `interactive-app`: PR-A ([#96](https://github.com/MitchReyno/InvenTree-Importer/pull/96)), PR-B ([#100](https://github.com/MitchReyno/InvenTree-Importer/pull/100)), PR-C ([#102](https://github.com/MitchReyno/InvenTree-Importer/pull/102)), PR-D ([#104](https://github.com/MitchReyno/InvenTree-Importer/pull/104)), PR-E ([#108](https://github.com/MitchReyno/InvenTree-Importer/pull/108)), PR-F ([#109](https://github.com/MitchReyno/InvenTree-Importer/pull/109)) and PR-G ([#110](https://github.com/MitchReyno/InvenTree-Importer/pull/110)). The styling uplift onto tokens v2 was planned in [#115](https://github.com/MitchReyno/InvenTree-Importer/pull/115) as tasks 15–20 (PR-H to PR-K), renamed onto tokens v3 in [#120](https://github.com/MitchReyno/InvenTree-Importer/pull/120), and extended with component alignment and tasks 21–23 (PR-L to PR-N, design D12). None of it has started. Re-sending a value InvenTree refused waits for executor follow-up work (design D7).

- **2026-11-06, task 12 (PR-C):** Native sessions already existed from [#97](https://github.com/MitchReyno/InvenTree-Importer/pull/97), so the adapter reports sessions where a session profile is configured, and `AgentSessionList` gained `sessions_supported`. - **2026-11-06, task 11.2 (PR-F):** With no preparation yet, Ready to add shows the reviewed lots ticked with "Show what will change" rather than preparing on arrival, so opening Changes never reads the target by itself.
- **2026-11-06, task 11.2 (PR-F):** By type has no purchase-order group, since no plan creates a purchase order. Tree nodes carry no links, so the arrow keys stay the tree's; By type rows link to Review.
- **2026-11-06, task 11.3 (PR-F):** Added's activity log lists rounds in approval order without times, since runs keep no timestamps.
- **2026-11-06, task 11.4 (PR-F):** Ready to add no longer offers stock-attachment downloads before approval. Their records are listed in By type and the Tree by name, with each new record's details.
- **2026-11-06, task 11.3 (PR-F):** The changes-commit spec's "fix in Review for a rejected value" is met only in part. The run read marks a supported effect `rejected: true` when its latest create got a 400 validation error with nothing attributed, and Added names the value and links to its Part record or lot in Review, or to the draft in Capture for a new location or supplier. - **2026-11-07, plan (D12):** No task may leave dead code. ## Unexpected challenges

- **2026-11-06, task 1 (PR-A):** A dark reload showed the page ground came only from `GlobalStyle`, after React rendered. The generated CSS now sets `html { background-color: var(--bg); color: var(--fg) }`, so the first frame of a dark reload is dark.
- **2026-11-06, task 2.6 (PR-A):** jsdom drops `var()` values, so the header dot's tone is exposed as `data-tone` for tests.
- **2026-11-06, task 2.6 (PR-A):** Prettier run from `frontend/` does not see the root `.prettierignore` and reformats the generated token files. Run it from the repository root.
- **2026-11-06, PR-B review:** Every operator-review issue has `disposition: null`, so status issues showed as decisions. Decisions now need `part_choice_required`, `quantity_required`, `location_required`, `location_conflict` or `location_draft_parent_invalid`, and approved lots count nowhere in Review or Changes › Ready to add.
- **2026-11-06, PR-B review:** jsdom does not raise the dialog's `cancel` on Escape, so tests dispatch `cancel` as the browser does.
- **2026-11-06, PR-B review:** Returning to Changes remounts the workspace on cached data, so a preparation approved elsewhere could be chosen. The bare choice waits for the mount's own read (`isFetchedAfterMount`) and, since that also turns true on an error, while the read is in error.
- **2026-11-06, PR-C review:** An instruction or answer save calls `reload`, which remounts `ProcessingStage` and lost the other draft. Each save is held back while the other draft is unsaved, and the other draft is locked during a save.
- **2026-11-06, PR-C (browser):** `Modal` had no background, so it was white in dark mode (also the evidence viewer); it now uses the surface token. The screenshot script's dark theme did not take effect in the PR-B and PR-C fixtures, so dark mode there was checked through the token and contrast checks and the PR-C demo.
- **2026-11-06, task 8.4 (PR-D):** `add_lot` takes no client ID, so "New lot from this" links the file once the refreshed batch shows a new lot whose label matches, and clears the pending link when the edit reports failure. The server stores `add_lot` labels unchanged, so the match holds.
- **2026-11-06, PR-D review:** A split or merge keeps media links on the retired lot, and the server counts a predecessor's evidence for its successors, so the Map showed files as unused. The Map walks predecessors from the operator review's retired lots to the server's depth of 100 and shows inherited files as "via earlier lot" with no Unlink; Part-derived links show "via shared Part". Until the next review is read after a restructure, the Map marks its flags "checking history".
- **2026-11-06, PR-D review:** A Processing job can be about a Part, so `openQuestionsByLot` gives each lot its own first open question, else its Part's.
- **2026-11-06, PR-E review:** A section save remounted every editor, because the detail was keyed by batch revision. It is keyed by record only, and Records keeps drafts across a reload so a refused save can be retried ("Load current values, keep this draft"). The batch's "Discard local edits" bumps a `discarded` counter in the detail's key so record drafts are dropped too.
- **2026-11-06, PR-E review:** `captureEditorChange` rebuilds a new Part's whole spec, so saving a label or location in the shared Part editor deleted a description set in Records. It now keeps the existing description.
- **2026-11-06, PR-E review:** A `location:draft:<id>` decision routes as `…/location/draft%3A<id>`, which the `AttentionItem.route` pattern refused, so the response failed its contract and every badge vanished. The pattern admits percent-encoded octets.
- **2026-11-06, PR-E (#107 merge):** [#107](https://github.com/MitchReyno/InvenTree-Importer/pull/107) makes approval refuse an agent lot that inherits the batch quantity until its estimate is accepted or replaced, but `projectRecords` resolved it to the batch default. Such a lot now shows its `estimated_quantity` with the `estimate` origin ("Estimated by Examine") and a `quantity_required` decision; one without an estimate shows no quantity.
- **2026-11-06, PR-F review:** The server records a refused create as unknown, not none, so the first "Fix in Review" rule flagged effects never sent and missed the refused one. That led to the `rejected` flag, limited to 400 responses because a 403 is not a refused value.

## Decisions made during implementation

- **2026-11-06, task 1.4 (PR-A):** Fonts: `@fontsource-variable/public-sans` and `@fontsource/ibm-plex-mono` (400, 500), both 5.3.0, OFL-1.1, pinned exactly and bundled by Vite through `GlobalStyle.tsx`.
- **2026-11-06, task 1 (PR-A):** The token generator, contrast check and literal-colour check are standalone `.cjs` tools run by the frontend `lint`, with their logic exported and tested in Vitest. The pre-paint theme script is inline in `index.html`, which is allowed because the app sends no CSP. The theme choice is stored under `bench-intake.theme`.
- **2026-11-06, task 2.6 (PR-A):** The sweep mapped the old palette onto tokens by role, not nearest hex, so the light theme takes the design system's values. `frontend/CODE_GUIDELINES.md` still asks migrations to preserve the current palette; that sentence is Mitch's and was not edited.
- **2026-11-06, task 3.2 (PR-A):** `check-masthead-mask.cjs` drives headless Chrome over the DevTools protocol with Node's built-in WebSocket, adding no dependency.
- **2026-11-06, task 3.3 (PR-A):** The light finish equals the previous constants exactly. Dark fills mix 72% towards dark `part-base`, and LED and display lit colours are unchanged. A theme change re-colours the same materials without rebuilding geometry.
- **2026-11-06, PR-A:** The design system artifact (its version 7 at the time) was given the same token changes as `tokens.json`, so the two stay copies. Tokens v2 for the styling uplift was published to it on 2026-11-07, ahead of task 15, and the same day v3 renamed the spacing scale to a 2px unit (`space-N` is N×2px) without changing values.
- **2026-11-06, task 5.5 (PR-B):** `ConnectionStatus.target.kind` is optional, and absent means configured, so older producers and fixtures stay valid. `owned_test` is set only for `INTAKE_TARGET_PROFILE=fake`, which the dev supervisor passes to the API child.
- **2026-11-06, PR-B review:** `Batch` remembers the last preparation shown and passes it to the workspace, which opens it if still current, otherwise the newest, with `location.replace` so Back does not loop. A bare Ready to add from the same preparation adds a history entry; linking the tab straight to the remembered preparation was rejected, because the header cannot tell whether it is still current.
- **2026-11-06, task 8.3 (PR-D):** One selection, held by `ManualWorkspace`, is shared by the Workspace and the Table. The Table can select more than 10 lots for bulk edits, as the contract allows; Mark reviewed and Prepare then refuse above 10, and Ready to add shares the same `MAX_SELECTED_LOTS`.
- **2026-11-06, PR-D review:** Files that share a name are numbered once over the whole media snapshot (`evidenceDisplayNames`), so a file reads the same in Capture, Review, Processing images and the Map. Identifiers appear only in a viewer's Details.
- **2026-11-06, task 9.5 (PR-E):** The records cap is 12,000: a Part yields at most 102 records, so 100 Parts give 10,200. A field's origin is the step of any retained proposal about the Part or one of its active lots that it still matches, because retained proposals are ordered by stage name and random ID, not recency.
- **2026-11-06, PR-E review:** A lot taking a new default location is listed under a record named after the draft. The draft lookup and parent check moved to `defaultLocationDraft` in `contracts/src/capture-location.ts`, shared with review, so a draft whose parent is invalid reads as a `location_draft_parent_invalid` decision.
- **2026-11-06, PR-E review:** A shared `SavingContext` disables every record Save and Remove while any record save is in flight, because the batch sends one edit at a time.
- **2026-11-06, PR-F review:** InvenTree links use `web/part/<pk>/` and `web/stock/item/<pk>/`, as the backend does, through the connection status's web address; with no address there is no link.
- **2026-11-06, task 14.7 (PR-G):** Proposals carry no likely-match field (BI-006 D13), so the projection finds an observed company in the role by an explicit rule, in order: the same name, its initials (GCT and Global Connector Technology), or one name containing the other as whole consecutive words; otherwise none. Words split on any script's letters and digits. A Part's catalogue comes from a current job before a superseded one, and from the Part before one of its lots.
- **2026-11-06, PR-G review:** Tell Examine and Ask keep unsent text and its idempotency key in `processing/pending-messages.ts` until confirmed or edited, so retrying an unconfirmed send cannot queue it twice, and report unsent text to the navigation guard. Discards clear Ask drafts.
- **2026-11-06, PR-G review:** A lot's newest status line (`subjectStatuses`) is taken from live sessions only, so a finished line does not hide a running one.
- **2026-11-07, task 15.1 (PR-H):** The screenshot diff (`pnpm screenshots:frontend`) is a standalone `.cjs` tool on headless Chrome over the DevTools protocol, like the masthead check, with its own PNG reader and writer on Node's `zlib`, so it adds no dependency. Its baseline stays local and gitignored (`frontend/.screenshots/`), recorded on the base commit, because screenshots are PR evidence, not committed files. Captures freeze animations and transitions and hide the masthead scene; with GPU emulation the anti-aliased rounded corners differed between identical runs, so it uses CPU rasterisation with a fixed sRGB profile, after which two compares of an unchanged tree matched in all 40 shots.
- **2026-11-07, task 15.2 (PR-H):** `tokens.json` is the design system's file verbatim (version `1794023843-2545`). Its editor writes every type style's `letterSpacing` as `"0"` and its weights as strings, so the generator treats a zero letter spacing as none (only the label is uppercase) and the generated whole-style `type` strings are byte-identical. The size family is split into typed maps by prefix (`size`, `icon`, `ring`, `offset`, `pageWidth`, the last avoiding the common local name `width`), breakpoints are exported as raw pixel numbers for media queries, and `typeVar` holds each style's parts. The 331 `space[...]` uses were renamed in one regex pass with no key renamed twice; tests, typecheck and lint pass and the screenshot diff is unchanged.

## Open items

- **Refused values (D7):** a corrected value cannot be re-sent until the executor can settle a refused create.
- **Exclude:** no command excludes a lot, so Exclude stays disabled and the "Excluded" filter is absent. Planned in task 22.4.
- **Records gaps:** the batch's new-supplier draft is not listed under Companies. Creating companies, categories and templates is shown as not supported yet. Leaving Records mid-save and returning can make a Save return unsaved with the generic message; "Load current values, keep this draft" recovers. Other refusals only the server knows about, such as tag rules, also return the batch's generic "Save not confirmed", with the same recovery.
- **Catalogue proposals:** at PR-G no session runner published a catalogue block (BI-006 task 10.4), so the GCT and new-category scenarios were proved with seeded `/5` proposals in unit tests and the browser fixture. Task 10.4 has since landed in [#112](https://github.com/MitchReyno/InvenTree-Importer/pull/112); the end-to-end proof with the session worker is now possible but not done.
- **Region crops:** the PR-G browser check did not re-check region crops in the evidence pane, because the fixture cannot serve the crop route; BI-006's own qualification checked them.
- **Unmet spec behaviour:** three behaviours were left for task 14, which did not deliver them: Review's inline answer for a lot's open question (review-workspace), Needs you ordered oldest first, and step-page corrections ("Correct a reading") (processing-workspace). The inline answer and corrections are planned in task 21, and oldest first in task 22.
- **Review URL:** Review reads its view from the URL at mount, so a hash change on an open Review page does not switch view.
- **Browser coverage:** Safari, Firefox and real GPUs (WebGL ran on SwiftShader) were not checked, and no check used a live provider session or a real InvenTree: only the owned fixtures and the owned fake.
- **Remaining tasks:** tasks 15–23 (PR-H to PR-N) remain. Syncing and archiving the change wait for Mitch's authorisation.
