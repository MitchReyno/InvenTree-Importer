## Decisions made during implementation

- **2026-11-23T19:36+11:00, task 8 (PR-A):** Settings › Agents and the other Settings sections keep their row descriptions (`SettingRow` `help`, `SettingsSection` `lead`) as visible text. They are the design system's row-description pattern, not standing explanations under a heading; the sweep moved only Processing, Agents and Review text. "Not supported yet" reasons, legends of table marks and consequences of an action stay visible.
- **2026-11-23T19:36+11:00, task 8 (PR-A):** `Popover` chooses its alignment when it opens (`chooseAlign`): it keeps the preferred edge while that side of the trigger has room and otherwise opens from the trigger's other edge, rather than letting the window edge push the panel away. The panel's width is read as it attaches, before Radix caps it to the room on the aligned side. Rejected: setting `align="start"` on the need-you panel only, which would leave every other popover with the same trap.
- **2026-11-24T03:41+11:00, task 11.1 (PR-F):** Settings › Agents controls, by save mode. Non-text, saving as they change: each provider's On and sign-in choice, the default provider, each step's provider choice, the sessions stepper, Suggest tags for new batches, and both Web research switches. Text, keeping an explicit Save: Instructions, the Part description style and, until task 13's model picker, each provider's default model and each step's model. Unchanged: the credential panels and Pause all agents, which are their own commands, and the deferred description rows, which send nothing.
- **2026-11-24T03:41+11:00, task 11.1 (PR-F), rollout and recovery of the save receipt migration:** migration `0035` adds the receipt table and the per-scope pruning watermark. Every intake process checks the exact migration list at startup and quarantines a mismatch, so the API and the session worker must run the same build. To roll out:
  1. Drain and stop every intake process (the web entry point, the session worker and any runner), as for any intake deploy.
  2. Take a backup (`pnpm --filter @invimport/intake-server operations backup`).
  3. Migrate and grant with the new build: the deployment's provisioning step (`operations/deployment-provision.ts`) runs the migrations and then `grantProcessing`, which gives the API role its receipt privileges. The development stack does both when it starts (`dev/setup.ts`).
  4. Start every process on the new build only.

  If the rollout fails after step 3, recover forward (fix and redeploy the new build), or restore the step 2 backup and start the older build. The older build can't run against the migrated schema, and the migration is never edited or reversed in place.
- **2026-11-24T04:14+11:00, task 11.3 (PR-F), server details the design left open:** a reused `save_id` with another scope, base revision or field digest is refused as `save_receipt_mismatch` (409), and `save_outcome_unknown` is also 409, with `refresh` recovery like `revision_conflict`. The digest is SHA-256 of `canonicalRecord` of every submitted field except `expected_revision` and `save_id`. The pruning watermark is a column on `agent_settings` (`receipts_pruned_through`), since receipts exist only for scopes with a saved row. A save with no receipt over a base revision below the watermark is answered `save_outcome_unknown` even on its first send: the server can't tell a first send from a resend, and such a save would have been a conflict anyway.
- **2026-11-24T04:14+11:00, task 11.3 (PR-F):** queued edits keep the revision they were made over, as the design says, so after a conflict in one subsection is reloaded, another subsection's edit queued over the old revision meets its own conflict rather than being sent over the reloaded one. Reload or Try again resolves each.
- **2026-11-24T04:14+11:00, task 11.3 (PR-F):** in the interim Providers form, Reload after an autosave conflict moves the form onto the reloaded settings and keeps the model text drafts; a later model Save sends them under the reloaded revision, as the operator's explicit choice after seeing the reload.
- **2026-11-24T04:14+11:00, task 11.3 (PR-F):** a save with no answer is resent automatically with the same `save_id` after 1, 2 and 4 seconds, then waits for Try again; this applies to text Saves too, and `SaveBar` offers Try again for that state. Turning off the last provider is refused whenever it is the only one on, including just after a fresh setup turns its first provider on.
- **2026-11-24T04:14+11:00, task 11.3 (PR-F):** a Web research change made before readiness reports no web access now saves like any other change, so the "Discard my edit" button outside the disabled row is gone; the disabled settings show the saved values.
- **2026-11-24T04:14+11:00, task 11.3 (PR-F):** the pre-navigation flush reaches `useNavigationGuard` as an optional second argument of `onDirtyChange`, so `App.tsx`, which PR-B is changing, is untouched. `AutosaveStatus` gains an `unresolved` state ("Couldn’t confirm this change", Reload only), optional `messages` and a `retryLabel` ("Try again" on Settings › Agents; Capture keeps "Retry"), and shows its retry button on a conflict when given one.
- **2026-11-24T05:10+11:00, task 11.3 (PR-F), review round 1:** expired receipts are pruned under the scope lock before the receipt lookup, so an idle scope never replays one; when that save is then refused, its pruning rolls back with it, and the next save that applies prunes for good. A reused `save_id` racing a save in another scope is refused at the receipt insert, rolling the save back. On the frontend, a step's new provider autosaves with its saved default model while a model typed for it waits for Save; the last-provider rule is checked again at dispatch (a Try again after another tab turned the other provider off keeps this one on); a replay whose follow-up read fails stays confirmed and retries only the read; each interim model Save and Discard covers only its own subsection; a save that fails before sending offers Try again; a debounce restarted while its save waits in the queue delays that save; and the guard resumes only the latest navigation.
- **2026-11-24T08:20+11:00, task 11.3 (PR-F), review round 2:** a step's provider choice and a model typed for it are tracked apart, and a model draft is dropped when its step's provider changed elsewhere, so a retry never writes a stale provider back. Each interim model Save validates only its own fields and keeps that scope through Try again. A provider whose saved default model is not a model ID is refused at its switch ("Save a valid default model before turning Codex on") and again at dispatch. The read after a confirmed replay shows Reloading…, and a Reload or leaving the page supersedes it. A failed Reload leaves "Couldn’t confirm this change" as it was. Receipt age is measured with `clock_timestamp()` after the lock, not at transaction start. Moving to another Agents subsection drops a departure waiting for its save.
