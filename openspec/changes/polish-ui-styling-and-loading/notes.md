## Changes to the plan

- **2026-11-24T03:14+11:00, task 4 (PR-B):** `useFreshRead` takes the read's options (`queryKey`, `queryFn`, `enabled`, `refetchInterval`, plus `current` and `restored`) and calls `useQuery` itself, rather than taking a query result as the design's signature shows. It has to wrap the query function to number each request for the verified-reads registry, so it owns the `useQuery` call. The returned result still carries the query, `phase`, `verified` and the reason, plus `commandsReady` and `settledAfterHint` with their dispatch-time checks.
- **2026-11-24T03:14+11:00, task 4 (PR-B):** the snapshot projections are subsets that stay valid instances of the existing contracts (`ProcessingSnapshot`, `ManualWorkspace`, `CaptureSnapshot`, `BatchRecords`), so the contracts' own validators check them on write and read and no contract schema was added. The Review workspace projection empties `runs` and `preparations`, so it is restored only on Review › Lots, never on Changes.
- **2026-11-24T03:14+11:00, task 4 (PR-B):** Records' records read stays on `useBatchRecords` until PR-C moves Records onto the layer; only its Processing read moves here, as planned. Its snapshot is written after each successful read this mount made, and restored records (only at the batch's current revision) show with every record edit disabled, the same fence a stale read uses.
- **2026-11-24T04:56+11:00, task 6 (PR-D):** `improve-agent-interaction` had not landed its PR-F (no branch, nothing on `interactive-app`), so this PR defines `WorkState`, `StatePill` and `EventTime` in `components/ui`, with the mapping (`workState`) in `header/workSegments.ts`. That change's PR-F adopts them. `ProgressSegments`' own segment words ("running", "waiting") stay as they are: that change's task 9 owns the bar's states.
- **2026-11-24T04:56+11:00, task 6 (PR-D):** `EventTime` is not applied in `components/settings/` (Settings › InvenTree's last check and saved-token times), because PR-F is changing Settings in parallel; PR-H picks those up. The media removal reason keeps its date-only "Used by the approval on 20 Nov", which is part of a sentence rather than an event time.
- **2026-11-24T04:56+11:00, task 7 (PR-D):** the lot table includes legacy (non-session) jobs, which the Pipeline left out, and drops the Pipeline's stale and provisional counts; the job cards on the step pages still show both.

## Unexpected challenges

- **2026-11-24T02:56+11:00, task 9 (PR-E):** The Capture fixtures' media clients refuse uploads on purpose, so the drop and paste checks and the demo used a throwaway copy of `GroupedCaptureProof` with a slowed in-memory upload, not committed. Headless browsers have no file manager or clipboard files, so drops and pastes were dispatched with a real `DataTransfer` of files. The installed Playwright has no matching WebKit build, so desktop Safari was not checked.
- **Task 2 (PR-A):** `screenshots:frontend` cannot capture `header-disclosure`: Public Sans never loads on that fixture, before and after this change. The other ten fixture pages are compared.
- **2026-11-24T03:14+11:00, task 4 (PR-B):** the revisionless-command audit (task 4.1) found three chat sends that name their session from the Processing read and carry no revision: Review Map's `TellExamine`, Records' Ask and Processing's sharper-photo request. TellExamine, Records' Ask and the sharper-photo request show the quiet "Updating…" reason and are checked again at dispatch. The session drawer's chat is not gated: the operator opened that session explicitly, and its own timeline read owns it.
- **2026-11-24T03:14+11:00, task 4 (PR-B):** no command on the Processing or Review keys writes its receipt with `setQueryData` today: Processing's commands, Pause and Review's answers already invalidate and reread. The rereads after receipt writes in PR-B are therefore those existing invalidations; Review Map's media receipt stays with PR-C.

## Decisions made during implementation

- **2026-11-23T19:36+11:00, task 8 (PR-A):** Settings › Agents and the other Settings sections keep their row descriptions (`SettingRow` `help`, `SettingsSection` `lead`) as visible text. They are the design system's row-description pattern, not standing explanations under a heading; the sweep moved only Processing, Agents and Review text. "Not supported yet" reasons, legends of table marks and consequences of an action stay visible.
- **2026-11-23T19:36+11:00, task 8 (PR-A):** `Popover` chooses its alignment when it opens (`chooseAlign`): it keeps the preferred edge while that side of the trigger has room and otherwise opens from the trigger's other edge, rather than letting the window edge push the panel away. The panel's width is read as it attaches, before Radix caps it to the room on the aligned side. Rejected: setting `align="start"` on the need-you panel only, which would leave every other popover with the same trap.
- **2026-11-24T02:48+11:00, task 9 (PR-E):** A paste is left alone inside a dialog as well as inside text fields. The file viewer and the crop dialog are modal, and a screenshot pasted while one is open would otherwise land in Ungrouped behind it.
- **2026-11-24T02:48+11:00, task 9 (PR-E):** A refused drop or paste shows its reason in a dismissable warning on the evidence panel, which clears on the next accepted drop or paste. The capture tiles had no reason to reuse, so this is the panel's own line. A refused drop is still taken by the target, so the browser doesn't open the file instead. The gate checks an archived batch itself rather than relying on Capture's `disabled`, so it names the reason.
- **2026-11-24T03:14+11:00, task 4 (PR-B):** a live hint is any validated `ready` or `changed` frame in the scope; the registry records one hint time per query client (one scope), so every revisionless command treats every hint as relevant. Narrower relevance would need the stream-to-resource mapping the frames don't carry. Foreground reconciliation is not a hint.
- **2026-11-24T03:14+11:00, task 4 (PR-B):** instruction delivery waits for a Processing read that started after the delivery was asked for as well as after the last hint, and asks for one by invalidating the Processing read. Requiring only "after the hint" would let a read that predates the save's own hint, if the hint lags, release the send. A Retry while pending replaces the wait; a send in flight is never repeated.
- **2026-11-24T03:14+11:00, task 4 (PR-B):** the quiet "Updating…" reason is used on each page's main commands while they wait only for their read: Processing's Queue, Cancel this attempt and Pause or Resume, Review's Mark selected reviewed and Prepare exact selected effects, Tell Examine and Records' Send. Other controls fenced by the same wait (answer forms, editors, selection checkboxes) stay natively disabled, as before; PR-C can extend the quiet form screen by screen.
- **2026-11-24T03:14+11:00, task 4 (PR-B):** `ServerStateProvider` prunes other scopes', expired and malformed snapshots when its scope starts and deletes its own scope's snapshots and waiting writes when it ends. Reads filter by scope themselves, so a page that renders before that effect still never shows another scope's snapshot.
- **2026-11-24T03:48+11:00, task 4 (PR-B), review round 1:** commands with no revision also need no newer read in flight ("settled"), so Pause, Resume, delivery and the chat sends wait out a background refresh. Commands with a revision still stay available through it.
- **2026-11-24T03:48+11:00, task 4 (PR-B), review round 1:** the Processing projection replaces attempt and message IDs with a fixed placeholder and drops session inbox sources from proposals, and the batch projection clears evidence observations' agent session IDs. No session identifier is stored, and each projection stays a valid contract instance.
- **2026-11-24T03:48+11:00, task 4 (PR-B), review round 1:** a scope that ends drops only its waiting writes; the next scope's prune deletes its snapshots. A development Effect replay therefore no longer wipes the current scope's snapshots.
- **2026-11-24T03:48+11:00, task 4 (PR-B), review round 1:** Review's "Answer here" and its open answer form wait quietly for this visit's own Processing read, and the answer is checked again when sent.
- **2026-11-24T04:01+11:00, task 4 (PR-B), review round 2:** instruction delivery reads Processing itself (`requestRead` with `fetchQuery` through the registry's tracked function), so it neither depends on a mounted Processing page nor stalls on a read that started before it; a failed read marks the delivery failed with Retry. Every dispatch-time check also requires the cache to hold the read the page rendered, so a command never acts on a selection drawn from an older read. Review's commands and candidate acceptance are checked again at dispatch.
- **2026-11-24T04:17+11:00, task 4 (PR-B), review round 3 (fixed, not re-reviewed):** a read that live reconciliation cancels keeps delivery pending and is read again, rather than failing it. Records' Ask stays closed while its records are restored. Only `cancelVerified`'s own revert keeps the proof through a state change, so a same-data `setState` or a forced idle status clears it. A proposal that relied on a session inbox message is left out of the Processing snapshot instead of failing the whole projection. The registry attaches to the cache in the provider's layout Effect, not during render, and the skeleton's loading announcement sits outside its busy region.
- **2026-11-24T04:56+11:00, task 6 (PR-D):** the seven states cover every retained state through one table. Cancelled reads Not started (nothing done, nothing running until it is started again), superseded and waiting for capacity read Queued, waiting for sign-in reads Waiting for you (signing in is the operator's), and an import step with an uncertain or mixed effect reads Waiting for you (Changes asks the operator to check it). A job still holding its slot reads Working whatever its logical state, and queued work in a paused batch reads Paused while a running turn stays Working. The Agents page keeps its existing rule that a paused batch's unfinished session reads Paused. The job card keeps a short reason beside the pill for sign-in, capacity, interrupted, cancelled and replaced jobs.
- **2026-11-24T04:56+11:00, task 6 (PR-D):** the masthead summary follows the spec's precedence literally: a fresh read whose work list is truncated says "Status incomplete" when no failed or waiting step is visible, even while sessions are visibly working. After a named failure or wait, the line under the headline lists the other entries and then the working count ("2 agents working"). A lane in use with no working session listed reads "Agent lane in use". Import runs are named "Import" after the four steps. Outside a batch, with nothing active or waiting, the headline is the neutral "Agent activity", and the popover says "No active work listed" rather than "Nothing running".
- **2026-11-24T04:56+11:00, task 7 (PR-D):** a step page shows its summary beside its heading, so "Research · 1 lot · 1 done" reads as the heading "Research" with "1 lot · 1 done" and the step's state pill. Lots are counted by their per-lot step state (each lot's own job, else its Part's), followed by the step's own session count when it has sessions (changed in review round 1). Examine says "N lots formed" with the lead's state.
- **2026-11-24T04:56+11:00, task 7 (PR-D):** a focused lot shows the "No ‹Step› output for this lot yet" entry whenever its state at that step is not Done, and its job card, if any, is highlighted too; once Done, the job card is scrolled to and highlighted. A Part's job is highlighted for each of its lots, with a line naming the lot. Until the attention read is available, the Overview's Needs you lists only the agent questions the Processing read holds, or says "Updating…", never "Nothing needs you".
- **2026-11-24T08:08+11:00, tasks 6 and 7 (PR-D), review round 1:** outside a batch the summary describes one batch (the first waiting for the operator, else working, else queued) and returns it, so the pill's segments and name show that same batch. On phones a failure, a wait or an incomplete read keeps its word beside the spinner. The Overview's Needs you says the list is partial when the attention read failed, keeping the agent questions, instead of "Updating…". A restored Processing tab keeps the `lot` focus, and leaving the focus lets a later visit to the same lot scroll again. Job cards and session rows take the batch's pause, and a superseded job says its inputs changed rather than claiming a newer attempt. The server menu's last check renders `EventTime` through a new `KeyValue` `content` slot.
