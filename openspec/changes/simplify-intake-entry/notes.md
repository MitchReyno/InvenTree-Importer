# Implementation notes

Resumable agent sessions (PR-A, [#97](https://github.com/MitchReyno/InvenTree-Importer/pull/97)), Examine lot forming (PR-B, [#107](https://github.com/MitchReyno/InvenTree-Importer/pull/107)) and the per-lot pipeline with selective rework (PR-C, [#112](https://github.com/MitchReyno/InvenTree-Importer/pull/112)) are merged into `interactive-app`. PR-D, the live provider qualification (task 13), ran on 2026-11-07 under Mitch's authorization; its evidence is in the PR-D description. `native-agent/2` keeps `native_unverified`, and BI-006 moves to Done once PR-D merges.

## Changes to the plan

- **2026-11-06, task 1 (PR-A):** The spike ([`spikes/mcp-session-tools/`](../../../spikes/mcp-session-tools/README.md)) settled design D2 and D3. `${INTAKE_TOOL_CAPABILITY}` expands in `--mcp-config` headers, so the 0600-file fallback was dropped. `--safe-mode` drops `--mcp-config` servers, so the `/2` Claude adapter does not use it; `--setting-sources ""` and `--strict-mcp-config` still keep out a planted user `CLAUDE.md`, settings hooks and settings MCP servers. `--allowedTools mcp__intake__*` is required, or `-p` denies every MCP call. Codex needs `default_tools_approval_mode = "approve"` and `features.goals = false`. D2, D3, the risks list, the proposal's MCP SDK row and the task 4 adapter scope were updated.
- **2026-11-06, task 2 (PR-A):** `ProcessingInputV6` is not added to the shared `ProcessingInput` union, because existing `/1` handlers decode that union and rely on `dependencies` and a subject; only the session handler decodes `/6`. `assessCatalogue` is a pure function over observations, so its tests run in the fast tier rather than PostgreSQL as the task text asked; task 10.4 covers it with observations read from the database.
- **2026-11-06, task 4 (PR-A):** `failed` was added to the session states (migration `0018`, `SessionState`), and the session lineage foreign key is deferred because `queueJob` writes the attempt before its job. Session commands are authorized by `executeSessionCommand` from the retained command row, not `loadProcessingAuthority`, which keeps accepting only `bench-research`; design D9 records this and task 5's text was aligned.
- **2026-11-06, task 4 (PR-A):** The adapters and runner were written before the fake-CLI tests, not test first. Two negative controls compensated: disabling the init tool check failed the extra-tool test, and disabling in-turn delivery stopped the delivery test completing.
- **2026-11-06, task 6 (PR-A):** A Processing start for a session profile queues only Research and Images. The start button had always asked for all five stages, and session profiles refuse Reading and Identifying (the Examine stage replaces them).
- **2026-11-06, PR-A review:** Review added a 15-minute provider turn deadline (`SESSION_TURN_DEADLINE_MS`, design D3). On expiry the child is reaped and the session settles `failed`, which the wake sweep never resumes, so a stalled CLI is not restarted in a loop. Wake workflow IDs became `resume:<attempt>:<turn_count>:<minute_bucket>` rather than inbox-high-water IDs; D3 and task 5 were corrected.
- **2026-11-06, task 7 (PR-B):** `capture_lot.changed_revision` was added beyond design D12's column list. Lot staleness needs the batch revision of a lot's last change, and the subject `revision` is a per-subject counter.
- **2026-11-06, task 8 (PR-B):** The Examine trigger is a sweep in the session worker loop (`processing/examine-trigger.ts`, on the `agent_writer` pool), not the planned per-batch DBOS debounce workflow; design D8 was updated. It needs the Processing queueing grants, so those moved forward from task 10 to `agent_writer` (D10 updated).
- **2026-11-06, PR-B review:** A real lead session could not see the batch, so a lead-only `read_batch` tool was added (revision, lots, Parts, observations with edits and suggestions). Agent writes gained capacity limits: 1000 observations per batch, 100 active observations per lot, and a new lot and its Part count together against the subject limit. The `intake_agent_writer_marker` role is created by trusted provisioning (`grantCaptureAgentWrites`), not by migration `0019`.
- **2026-11-06, PR-B review:** A Review split left every observation on the retired lot with no way to move it. The split dialog now assigns each observation to a new lot (by a stable key per new lot), and a Move to… control places unassigned observations and those left on retired lots.
- **2026-11-06, PR-B (#104 merge):** #104 makes Review always open a lot, so the unassigned observations list moved from the empty state into the evidence panel under the open lot. `frontend/ARCHITECTURE.md` says so.
- **2026-11-07, task 10 (PR-C):** Examine lead sessions go ahead of per-lot sessions in the slot queue. A stable identity queues two sessions per lot, so at the default limit of 3 a lead resumed for new evidence waited behind every successor it had started. Design D9 records this.
- **2026-11-07, task 10 (PR-C):** The lead's identity proposal must cite the lot's current observation set as `{kind: 'observation_set', lot_id, version}`; `read_batch` returns each lot's `observation_set_version`. The lead's `propose` runs on the `agent_writer` pool. Session profiles may start Inventory only once the lot's Research and Images each have a current proposal (`inventory_waiting`, 409).
- **2026-11-07, PR-C review:** A successor that is queued and has never run (`turn_count` 0) is replaced on a republished identity; one that has run gets a `revision` inbox item. An operator regroup sends the lead a revision notice per identity it made stale. Staleness cascades through `proposal` sources until nothing new is stale, with a depth bound of 8 (`cascadeAll`), for regroups, removals, answers and corrections. No claimant counts a queued Inventory ahead of it. Design D9 and the architecture docs were updated.
- **2026-11-07, task 12 (PR-C):** Browser qualification found that a resumed Research or Images session, woken by a revision, was superseded once its pinned identity went stale. The pinned-identity check now runs only before a session's first turn (`turn_count` 0).

## Unexpected challenges

- **2026-11-06, task 3:** The process tier had one failing test before this branch: `tests/process/media-resources.test.ts` expected the decoder's 512 MiB limit after #93 raised it to 1024, with 3 dependent skips. It was left for the media change and fixed on trunk by #98. CI then stopped running the PostgreSQL and process tiers (#99), so from PR-B onward those tiers run locally.
- **2026-11-06, task 7:** The agent guards first used `pg_has_role`, which is true for superusers and refused the migration owner and test setup. They now check inherited membership of the marker role and exclude superusers.
- **2026-11-06, task 7:** An unexpected handler exception left the MCP call hanging until the client's 60-second timeout. The server now returns a typed `tool_failed` result and logs the tool name with a safe code.
- **2026-11-06, task 7:** Observation regions carry integers, which `canonical` rejects. `canonicalRecord` (contracts `json.ts`) is used for capture revisions, idempotent request and response bytes and snapshot size checks; for documents without numbers it produces the same bytes.
- **2026-11-06, task 8:** System inbox notices inserted through Drizzle listed `actor_id` and `created_at`, which the system roles deliberately cannot write; notices with no actor use a plain insert of the permitted columns. `readAgentSettings(..., lock=true)` needs `UPDATE` on `agent_settings`, so the trigger reads the selection without the lock.
- **2026-11-06, PR-B review:** Migration `0019` created a cluster role, which failed under the `NOCREATEROLE` dev migrator and broke the `dev-stack` and `dev-environment` process tests. Provisioning now creates the marker, and `is_agent_writer()` returns false while it is absent.
- **2026-11-06, PR-B review:** An oversized lead manifest was retried every sweep, because `processing_input_capacity` is raised as a `ProcessingError` and the trigger only read `CaptureError` codes. It now reads both.
- **2026-11-06, PR-B qualification:** "Owned probe must become observable" failures were environmental: `build-media-probe.cjs` leaves the probe image untagged, so it had been pruned, and every probe failed with `decoder_interrupted`. The build also refuses to overwrite an existing `--output-file`, so rebuild to a new path.
- **2026-11-07, task 10:** A tier run hung for about 2.7 hours in `processing-suggestions.test.ts` because it was started without `INTAKE_MEDIA_DECODER_IMAGE`. Tier runs now get a hard time cap and a stall check.
- **2026-11-07, task 11:** An eager import of `currentness.ts` from capture formed a load-time cycle through the media modules (Processing depends on capture), so capture loads it lazily. On a manual-only deployment the capture `api` role has no Processing grants, so the currentness and regroup hooks check `has_table_privilege` and do nothing there.
- **2026-11-07, PR-C review:** On `native-agent/2`, queueing from the lead identity failed because `createSessionAttempt` read Agent settings `FOR SHARE`, which `agent_writer` cannot. That path passes `lockSettings: false`, as the Examine trigger does.
- **2026-11-07, task 13:** Codex (codex-cli 0.166.0, `gpt-6-luna`) was not confined to the intake tools. It wrapped the `mcp__intake__*` tools inside its `exec` JavaScript tool (code mode), so they were not top-level tools. It also offered `wait`, `request_user_input_async`, the `collaboration` and `clock` namespaces, `apply_patch` and `image_gen`, and loaded the user-level skills catalogue despite the dedicated `CODEX_HOME`. The adapter's start-time check compares only MCP server tools, so it sees no built-ins, and the in-run item check sees only the nested MCP calls, not code run inside `exec`. Codex's first call ran arbitrary JavaScript, and the session was not refused.
- **2026-11-07, task 13:** `propose` rejects with `validation_failed` ("Arguments do not match SessionProposeArgs: invalid_contract") and does not name the failing field. Codex's single lead `propose` was rejected and never retried, so no identity became stable. Claude (`claude-haiku-5-5`) LED Research was rejected four times, with object arguments, before it published a minimal proposal; its own explanation, that it had sent a JSON string, was wrong.
- **2026-11-07, task 13:** A session cannot cite evidence it picks up mid-session: the inbox payload carries only `evidence_id` and `version_id`, and `fetch_evidence` returns no digest. On resume, Claude LED Images tried to cite the new photo with an invented all-zero `sha256`, and the server correctly refused it with `source_not_delivered`.
- **2026-11-07, task 13:** Claude sessions were also offered a deferred `advisor` server tool (`advisor_20260301`) and a non-callable `DeferredToolPlaceholder`. The start-time check does not see `advisor`, because it is not in the init tools list, and it could not be loaded because no tool-search tool was offered.

## Decisions made during implementation

- **2026-11-06, task 1:** MCP SDK: `@modelcontextprotocol/server` 2.4.0 with `@modelcontextprotocol/node` 2.1.2 (Apache-2.0, Node 20 or later), with `@modelcontextprotocol/client` 2.4.0 as a dev dependency, all pinned exactly. Rejected: `@modelcontextprotocol/sdk` 1.32.2 (MIT), which passed every check but brings Express 5, `cors`, `express-rate-limit`, `hono` and `ajv`. The server takes no direct `zod` dependency; tool schemas are the contract JSON Schemas. `THIRD-PARTY-NOTICES.md` lists no installed npm package, so the SDK adds no entry. Toolchain at the spike: Node 24.22.2, Fastify 5.12.7, Claude Code 2.1.318, codex-cli 0.166.0.
- **2026-11-06, task 1:** The endpoint uses Fastify `reply.hijack()` and a stateless `McpServer` per request, built with the tools of the session the capability belongs to. Validation stays in the handlers, so invalid calls get typed results rather than protocol errors.
- **2026-11-06, task 1:** Four Codex built-in tools have no config key to remove them (`list_mcp_resources`, `list_mcp_resource_templates`, `read_mcp_resource`, `request_user_input`). They are accepted as an exception in D2: the intake server declares no resources, Codex answers `request_user_input` itself, and the adapter still refuses every server-initiated request.
- **2026-11-06, task 4:** Both adapters poll the inbox every 500 ms during a turn and deliver in turn (Claude stdin stream-JSON, Codex `turn/steer`); `read_inbox` stays the guaranteed path. A refused steer leaves the item pending. Items the CLI accepted are acknowledged only when the turn succeeds.
- **2026-11-06, tasks 3 and 5 (PR-A review):** Limits chosen: `status` at most one per 2 seconds; `session_concurrency` 1–8, default 3, under DBOS's cap of 8; a workflow waits at most 30 seconds for a slot before giving its worker back; at most 100 proposals per attempt and 100 questions per job, and retained session proposals and questions within half the 240 KiB Processing snapshot budget, each counting a 512-byte projection allowance. The 8 MiB image budget is per provider run, reserved before fetching.
- **2026-11-06, PR-A review:** A session may cite media only once `fetch_evidence` has returned it in the lineage. This is tracked in the worker, so after a restart the session must fetch again before citing.
- **2026-11-06, PR-A review:** Confirming a reaped child and clearing its slot is an explicit maintenance step, as for the `/1` lane; the supervisor refuses to start while any session slot is occupied.
- **2026-11-06, PR-B review:** The Examine trigger skips a batch only on failures that repeat until the evidence changes (`media_input_capacity`, `processing_input_capacity`); other errors retry next sweep. The skip signature includes the capture and media batch revisions and decode results, so editing an oversized note retries the batch.
- **2026-11-06, PR-B review:** An AI lot whose quantity is still inherited raises `quantity_required` even when the batch default is set, so estimates cannot pass as counts. A lead `quantity` question must name a live lot; a clarification answer with no subject becomes a batch note.
- **2026-11-06, PR-B review:** Accepted: the agent guards check that `agent_session_id` is present, not that it belongs to the batch, since application code always passes the writing session.
- **2026-11-07, task 11:** An answer supersedes only the question's declared `fields`, so a quantity answer leaves identity proposals current. A null-subject answer affects no proposals. The answer path applies its value through `capture.apply`, not `edit`, so it is not counted twice as a correction.
- **2026-11-07, task 12:** The Examine view numbers photos by their first observation, because the capture snapshot carries no photo labels.
- **2026-11-07, PR-C (#110 merge):** `assessCatalogue` moved into contracts with #110, and `applicableCatalogueSpec` builds on it. Records treats a proposal as current only while its job is not superseded and its own `currentness` is not stale, and prefers current proposals for field origins and the catalogue choice.
- **2026-11-07, task 13:** `native-agent/2` keeps the `native_unverified` label. Claude passed every check except status cadence, which was partial (status lines at milestones, not at each step); Codex failed the tool-only allowlist and the identity proposals. The label is set per profile, and one run per provider on a cheap model qualifies neither. Task 13's acceptance is the documented outcome, not a passing label, so BI-006 moves to Done once PR-D merges.

## Open items

- **Codex tool surface (from task 13):** expose the intake MCP tools directly, with `exec` (code-mode) wrapping turned off, since turning off `exec` alone would cut off every app tool. Remove `wait`, `request_user_input_async`, the `collaboration` and `clock` namespaces, `apply_patch`, `image_gen` and the skills catalogue, keeping D2's four accepted exceptions. Check the full offered tool surface at start, including built-ins, and refuse code run inside `exec`.
- **Proposal validation messages (from task 13):** `propose` should name the field that failed validation.
- **Citable new evidence (from task 13):** deliver a digest for evidence picked up mid-session, in the inbox payload or the `fetch_evidence` result.
- **Claude `advisor` tool (from task 13):** exclude or detect the deferred `advisor` server tool in intake sessions.
- **Qualification script (from task 13):** count a chat as handled when the session asks a question or posts a status after reading it, not only when it replies in chat.
- **`/1` Codex goal tools:** `features.goals` defaults to on in codex-cli 0.166.0, so a `/1` Codex turn is also offered the goal tools and `request_user_input`. `/1` was out of scope; raise it separately if wanted.
- **Resume routing:** routing a resume to the matching worker is not solved. One actor's worker per DBOS application is the supported deployment; a mis-routed claim changes nothing.
- **Dev launcher:** dev setup does not create the `agent_writer` role and the dev launcher does not start a session worker. Without `INTAKE_AGENT_WRITER_DATABASE_URL` the lot-forming tools refuse with `tool_not_allowed`.
- **Review remount:** each adopted live revision remounts the Review workspace, so an inspected lot's local view state resets when the lead session writes. Drafts are protected because adoption waits while any draft is dirty.
- **Answers count as edits:** an answer to a lot's quantity applies the operator's capture `lot` edit, so the lot becomes `operator_edited` and later evidence for it arrives only as a suggestion. Whether an answer should block grouping is left open.
- **Fan-out gaps:** bulk and operator-review edit paths do not fan out yet. A Records edit to a Part's spec is not an operator correction (design D7), so it sends no notice and makes nothing stale. A session pinned to a proposal that goes stale two or more levels down, and that has published nothing, gets no notice; Inventory still waits.
- **Untested interleavings:** ranking across target contexts, the latest-session sweep filter, archived ranking, cancelled-session cleanup and recovery interleavings, resume racing a fresh start, and a cascade deeper than two levels have no dedicated tests.
