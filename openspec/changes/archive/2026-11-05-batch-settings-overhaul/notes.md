# Implementation notes

Delivered into `interactive-app` through PR-A [#85](https://github.com/MitchReyno/InvenTree-Importer/pull/85) (Tasks 1–2), PR-B [#87](https://github.com/MitchReyno/InvenTree-Importer/pull/87) (Tasks 3, 4 and 9), PR-C [#88](https://github.com/MitchReyno/InvenTree-Importer/pull/88) (Tasks 5–6) and PR-D [#89](https://github.com/MitchReyno/InvenTree-Importer/pull/89) (Tasks 7–8), with main specs synced in [#90](https://github.com/MitchReyno/InvenTree-Importer/pull/90). Purchase-order support (BI-005) and automatic supplier logos (BI-004) remain separate Proposed items.

## Changes to the plan

- **Planning, task 9 (PR-B):** The Capture layout and subject-pane removal came from a later planning request and was added as Task 9 inside PR-B. Existing task numbers were kept stable, so numbering does not prescribe execution order.
- **2026-11-04, tasks 2–3 (planning):** A follow-up planning request added typo-tolerant fuzzy search to the shared picker. Research found React Select's default filter only matches substrings, so Fuse.js 7.1.0 was recommended, and candidate retrieval was made independent of strict upstream filtering with a 500-candidate cap. The proposal, reference spec, design, Tasks 2–3 and the BI-003 summary were updated.
- **Task 3 (PR-A):** The first PR-A commit reconciled the plan so Auto/None/Manual fields use Radix Popover dropdowns with a dedicated manual-input area, and React Select serves only the supplier, Default location and parent-location pickers. The design, proposal, PO spec requirement and Task 3 were updated.
- **Task 1 (PR-A):** Part/group location assignment models moved to Task 5, Processing consumption of notes and Auto tags/quantity to Task 6, and draft execution to Task 7. Task 1's "assignment provenance" was taken to mean the actor/version provenance of retained intent, notes and drafts.
- **Task 9 (PR-B):** `CaptureQueue` and `InstructionsPanel` were deleted outright rather than only removed from composition. Write a note now opens `EvidenceNoteForm`, an explicit append-only batch note, instead of focusing the settings note.
- **Task 6 (PR-C):** The design called for a versioned automation-intent input. Instead, Auto tags is carried as a server-derived labelled capture-context note, so legacy batch inputs keep their bytes; quantity and tag suggestions arrive in a new `bench-intake-proposal/4` output.
- **Task 6 (PR-C):** The Task 6 plan said no new input versions, but review found tag acceptance had no reachable path: processing inputs refused subjects with a `create` choice, and tags can only be added to a `create` spec. Mitch chose a new create-capable input, `bench-intake-input/5`, which is otherwise identical to `/2` and is built only when the subject or linked Part has a create choice.
- **Task 7 (PR-D):** No separate logo effect was added. An optional logo is sent as the company `image` in the same multipart create request, which Mitch chose over a separate PATCH or attachment effect.
- **Task 8 (PR-D):** The 8.1 journey is server-level: it sends the HTTP commands the UI sends but does not drive the autosave coordinator, connection recovery or Review acceptance control, which are covered by their own frontend suites. Review found the earlier 8.1 description overstated this, and the text was corrected.

## Unexpected challenges

- **Toolchain:** The shell defaults (Node 22, pnpm 8) do not satisfy the repository pins. Work used Node 24.22.2 and pnpm 12.16.1, and PR-A added a `.nvmrc` with the same pin as `.node-version`. The full PostgreSQL tier also needs Docker's CLI on `PATH` and `INTAKE_MEDIA_DECODER_IMAGE` set to a retained decoder image.
- **Task 1 (PR-A):** A title-only `batch_settings` save rederived every legacy field and collapsed retained `unknown` supplier/date and `clear` tags to `unset`. `nextLegacyContext` now rederives only fields whose intent changed, compared with key-order-independent structural equality because `JSON.stringify` treated reordered keys as a change.
- **Task 2 (PR-A):** InvenTree uses `LimitOffsetPagination` with no default page size, so a list request without `limit` returns the whole catalogue. The adapter always sends `limit` and `offset`, accepts only the paginated envelope and rebuilds the next request rather than following upstream `next` URLs.
- **Task 2 (PR-A):** The snapshot's 15-second budget did not cover waiting for response headers, so a read could run to about 20 seconds. The transport `list` now accepts a caller timeout that can only shorten its 5-second deadline, and each request and body read gets only the remaining budget.
- **Task 3 (PR-B):** React Select drops a passed `aria-describedby` and hides a disabled input with `visibility: hidden`, removing the named combobox from the accessibility tree. The picker uses a module-scope custom `Input` that appends its status ID and keeps the input visible. A controlled `inputValue` must also be cleared on `set-value`, `input-blur` and `menu-close`.
- **Task 4 (PR-B):** RHF mutates nested form values in place, which silently rewrote the queue's frozen saved payload so a No supplier change compared equal and was never sent. `settings-model.ts` now builds the command as a deep copy.
- **Task 4 (PR-B):** StrictMode's effect replay disposed the save queue permanently, so development autosave never sent. `useSaveQueue` re-activates the queue on effect setup; a genuinely unmounted queue still never dispatches.
- **Task 4 (PR-B):** `Batch` rebuilds its settings ports on every render, which replaced Capture's dirty callbacks and made `useDirtySources` report clean while an upload was pending. Capture now reads current ports and callbacks through a ref, and `useDirtySources` reports clean only on unmount.
- **Task 9 (PR-B):** Browser qualification found the settings panel's leftover `grid-area` squeezing it into an implicit narrow column below 860px. It was removed.
- **Task 6 (PR-C):** The requested-automation note counted as evidence, so with Auto tags on and no other evidence it admitted an input and could be the only source of a quantity estimate. `isAutomationIntentNote` excludes it from admission and provenance refuses any proposal citing it; producers (provenance, the development runner, the native prompt, the process-test worker, the browser fixture and `research-protocol-child.cjs`) now cite only `evidenceNotes`.
- **Task 7 (PR-D):** The owned fake answered any location or company GET with a synthetic record, so it could not prove a created output. It now persists created locations and companies (PKs from 12001) and returns stored rows or 404.
- **Task 7 (PR-D):** Reuse of a record confirmed by explicit verification after an uncertain create failed because `requirePriorRecord` read the immutable effect row rather than the journal-derived state. Reuse now requires the derived state to be confirmed with the original create intent and PK and no failed inspection.
- **Tasks 7–8 (PR-D):** Review found reused records were not rechecked during execution, so a run could stock into a location or supplier later inspected as changed. New stock creates now wait unless every reused record still passes `requirePriorRecord` and any same-run location has not failed inspection (`stockWritable` in `effects-apply.ts`); read-only inspection of existing stock still runs.
- **Tasks 7–8 (PR-D):** Supplier draft edits did not invalidate review because the draft entered only selection material. Each lot's review facts now carry `supplierDraft` when a supplier draft is selected; facts without one keep their exact bytes.
- **Task 8 (PR-D):** The browser run found Review facts showing the drafts as "Not selected" and "Explicitly unknown". Both now name the pending draft.

## Decisions made during implementation

- **Task 1 (PR-A):** Edits use a new complete-state `batch_settings` change, and the server writes only what differs from retained state under one revision bump. Old `settings`/`defaults` kinds stay accepted, but a legacy `settings.context` write after an intent exists is refused with `settings_intent_superseded` so two authorities cannot diverge.
- **Task 1 (PR-A):** Each intent change also writes the derived batch-level legacy `capture_context` row, so Processing, Review fingerprints and lot inheritance keep their inputs. Without an intent, legacy values map at read time (set to manual or existing, clear to none or absent, unset and unknown to Auto, tags to manual with Auto off); nothing is rewritten.
- **Task 1 (PR-A):** Migration `0014_capture_settings_intent.sql` adds four append-only tables; drafts carry a composite FK to `media_version` so a logo is proved same-batch retained media. Limits: order reference 1–128 characters, notes 1–8192, at most 16 active drafts, draft names 1–100 and descriptions up to 250, logo PNG/JPEG only.
- **Task 2 (PR-A):** Target shapes were checked against InvenTree source at tag `1.5.0` (API version 530), not the latest documentation. Each model has a search route (one strict page of at most 50, plus exact detail read for a numeric query) and a candidates route (up to 500 records in pages of 100, disclosing `truncated` and `total`).
- **Task 2 (PR-A):** Bounds are query 1–100 characters, offset at most 10,000, 512 KiB per page and at most two concurrent catalogue reads per server process (`catalogue_busy`). Any invalid response is `catalogue_unavailable`, and selection binds through the existing `observations` command. `structural` locations are returned with that flag for the picker to label, not filtered.
- **Task 3 (PR-B):** Fuse.js is pinned at the planned 7.1.0 although stable 7.5.0 exists; the 7.6 prerelease is not adopted. React Select 5.10.2 brings Emotion as a second styling runtime, contained in `SearchableReferencePicker` through one `styles` adapter with no animated components. The install added 55 lockfile packages, no new advisory and about 37.5 KB gzip to the production bundle.
- **Task 3 (PR-B):** The ranker puts exact ID, exact name and name-prefix tiers before Fuse suggestions, weights names 3:1 over path/description, uses threshold 0.4 and no fuzzy matching below three characters. Name matches precede secondary-only matches, ties break by numeric ID compared with `BigInt`, and an all-digit query matches IDs only.
- **Task 3 (PR-B):** Shared tags are deduplicated case-insensitively keeping the first spelling, limited to 32 tags of 100 characters, and delimiters wait for IME composition to end. Review's tag merge uses `tagKey`, which folds only all-printable-ASCII names to match the inventory adapter.
- **Task 4 (PR-B):** `SaveQueue` is the per-batch owner with `settings`, `instructions` and `logo` lanes and one request in flight across lanes. A logo receipt carries no revision, so the queue takes expected + 1. Capture is keyed by `batch.id:reset` only, so own acknowledgements no longer remount it.
- **Task 4 (PR-B):** Editing needs a fresh scoped observation (the header connection read or the batch's capture read) within 60 seconds and the browser not offline, re-evaluated by a five-second clock and on focus/visibility. Socket health is not an input, and reconnection reads the batch before admitting writes.
- **Task 4 (PR-B):** Evidence media/note commands and settings commands stay separate owners, serialized by fencing each other rather than sharing the queue. Settings stay paused after an evidence change until the newest refresh of the new revision is accepted.
- **Task 4 (PR-B):** A lane with an unconfirmed or conflicted request keeps every draft, so reverting to the old saved value is still sent. IME composition suspends all dispatch queue-wide, and clean adoption of a newer snapshot also waits for it. Review added "Discard unsent settings edits" for drafts made while disconnected.
- **Task 9 (PR-B):** Review's `ReviewSubjectEditor` (`?edit=<id|add_lot|add_part>`) hosts manual lot/Part add and edit, with separate fences for the subject form and attachment choice. Review lists "Edit unlinked shared Part" for Parts linked to no lot. Legacy `#<batch>/<subject>` links redirect to Review with `location.replace`.
- **Task 5 (PR-C):** Part and group assignments are only `set` or `clear`. A lot value other than `inherit` wins, including `unset`/`unknown`, which still block; differing group assignments with no higher value block with `location_conflict`; and unavailable media blocks resolution rather than guessing when any group assignment exists.
- **Task 6 (PR-C):** A quantity estimate can be accepted only as an explicit human edit, while the attempt is `ready` from a mounted Processing read at the displayed capture revision, and while the lot has no human count, including an inherited exact batch default. Tag suggestions are accepted only when Auto was requested; existing Parts' tags are never changed.
- **Task 7 (PR-D):** An approved new-supplier draft is created inside the batch's stock run with `is_supplier: true` and `is_manufacturer` from Also set as manufacturer, adding no supplier-part links. Mitch chose this.
- **Task 7 (PR-D):** Record creation uses new `bench-effects-plan/2`, `bench-effects/2` and `owned-fake-effects/2` versions so `/1` plans, manifests and recovery stay byte-for-byte; each deployment row and runner runs exactly one build. Every created location must be consumed by a stock operation, and a company is a declared standalone output.
- **Task 7 (PR-D):** Lots using an unset batch default resolve to a Default-location draft instead of `location_required`, with the draft version in the review material. Known outputs are reused by target, original source key and `draft_id`, and no name lookup ever adopts or proves a create; an unknown create is settled only by explicit `verify_effect` of an attributed PK.
- **Task 8 (PR-D):** Rollback sets `INTAKE_DEPLOYMENT_ID` to a `/1` deployment and keeps the `/2` deployment row and runner until retained `/2` runs settle. `executor_record_identity` is never dropped.

## Open items

- Draft persistence across a browser crash or reload is not promised; only beforeunload protection applies.
- A logo is uploaded through the ordinary batch media upload and is any same-batch retained PNG/JPEG version, so it also appears as evidence. No dedicated logo upload path was added.
- Older frontend builds fail closed on the new snapshot fields and need a reload.
- Group location membership comes only from evidence linked to the lot itself, not evidence linked only to its shared Part. Split and merge copy only lot-level locations.
- Quantity and tag suggestions come only from the deterministic fixture path. The native runner and live inference are unqualified.
- Record creation is qualified only against the owned fake and only on `owned-fake-effects/2` deployments; the development stack stays on `/1`. InvenTree's required Company `currency` and image storage are not exercised, and real-target creation stays unavailable.
- No same-name reconciliation command exists; choosing an existing record of the same name is an ordinary new selection that never settles an unknown create.
- React Select's last release was 2025-07-11, a maintenance risk to watch.
- PO creation ([BI-005](../../../../docs/PLANNED_FUNCTIONALITY.md#bi-005--purchase-order-support)) and automatic logo discovery ([BI-004](../../../../docs/PLANNED_FUNCTIONALITY.md#bi-004--automatic-supplier-logos)) remain disabled placeholders. Browser qualification is recorded in the [evidence record](../../../../docs/bench-intake/evidence/batch-settings-overhaul/README.md).
