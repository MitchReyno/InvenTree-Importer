# Coverage ledger

Every heading in every document under [`sources/`](sources/) has a row below. Each row says where that section's content went:

| Disposition | Meaning |
| --- | --- |
| `spec` | Written as requirements in this change's specs |
| `covered` | Already owned by an existing or later spec, named in the row |
| `superseded` | Later work changed it; the old statement is in the design and is never synced |
| `design` | Rationale, alternatives, decisions, unbuilt intent or differences from the code, recorded in [design.md](design.md) |
| `history` | Delivery status and history, condensed in the design |
| `not carried` | Navigation or obsolete process text that newer repository rules replace, with the reason |

The sources stay in this change, unchanged apart from link repairs, so nothing in them is lost. The ledger records what is current and where.

Check completeness by listing every `#`, `##` and `###` heading under `sources/` and matching each to a row here. On 2026-11-07 that matched all 259 headings, counting the two navigation-only preambles listed directly below.

| Source section | Disposition | Where | Proof / notes |
| --- | --- | --- | --- |
| `sources/typescript-data-model/01-identity.md#1. Identity and inventory context` (preamble) | not carried | — | Contains only a link to the model index |
| `sources/typescript-data-model/05-transactions.md#5. Transactions, queries and operations` (preamble) | not carried | — | Contains only a link to the model index |

Abbreviations in the "Where" column name a capability spec and requirement (for example `AE / Apply single physical writer` is `specs/apply-execution`). A `D ›` prefix names a heading in [design.md](design.md).
