# First-slice runtime contracts

`src/index.ts` registers strict runtime schemas; `src/scalars.ts` retains the unchanged shared exact scalars. `src/capture.ts` owns manual-capture DTOs, and `src/manual.ts` owns exact review/preparation/approval/run/activity DTOs. `generated/openapi.json`, `generated/api.d.ts` and clients are reproducible outputs (`pnpm contracts:generate`; verify with `pnpm contracts:check`). Clients validate returned DTOs; TS declarations alone never validate data. OpenAPI advertises implemented health/bootstrap, capture and manual review/preparation/approval/run/start/cancel/recover/activity endpoints. Earlier generic worker components remain tested contracts, not active provider routes or authorization. JSON Schema Draft 2020-12 worker envelopes are independently versioned `bench-intake-worker/1`, distinct from HTTP `bench-intake-app/1` and canonical encoding `bench-intake-canonical/1`.

## Generated clients and runtime policy

OpenAPI is the source for generated paths, request/response types and operation validation/deadline policy. `openapi-typescript` generates `api.d.ts`; schema-name aliases preserve existing DTO imports. A private generator workspace uses its declared-compatible TypeScript 5 peer while application compilers remain TypeScript 6. It is a development-only dependency, outside the browser runtime graph.

`openapi-fetch` owns typed request construction and response inference. The small compatibility facades in `src/client.ts` retain captureClient, manualClient and intakeClient. `src/client-policy.ts` validates request bodies before transport and responses at runtime through the existing AJV schemas, injects CSRF, preserves safe errors, refuses redirects and applies each operation's deadline. The generated `client.ts` re-exports that runtime boundary; it no longer contains a separately maintained transport implementation.

Injected transports still receive a URL and RequestInit, preserving existing consumers. Request/body serialization retains exact string scalars and caller-supplied idempotency keys. No retry, inventory credential, target-selection authority or persistence capability is supplied by the client package.

`captureClient` uses same-origin POST commands, a bootstrap CSRF token and caller-retained UUID idempotency keys. Errors retain safe HTTP status/code (`IntakeRequestError`); 412 means explicit comparison/reload, not automatic replay. `CaptureSnapshot` includes original source/contribution identity, separate shared Parts/lots, explicit selection modes, human notes/actor, retained read observations and a consistent cursor. An observation is not a selection. Omitted edit fields remain unchanged; unset/unknown/clear/inherit are separate values. Defaults cannot inherit at the repository boundary. `manualClient` sends explicit selected scope, frozen plan digest/review/target revision, and original-run revision commands. At most ten unique lots are accepted; larger scope fails before preparation. Capture alone is never approval. Run results retain per-operation certainty, confirmed/attributed stock IDs, safe-recovery availability, numeric round order and a consistent cursor.

Boundaries preserve unknown/omitted versus `inherit`, `clear` and `set`. IDs are validated lowercase UUIDs; revisions/PKs are positive signed-64-bit strings and cursors may be zero. Quantity strings are positive, canonical, at most 13 integer/6 fractional digits; no numbers, exponent, sign, trailing fractional zeros or whitespace. Explicit Part/location references carry target-context and retained observation identity, not raw browser target URLs. Selected lot arrays reject duplicates and remain ordered at parsing; selected-scope owners sort them as sets before semantic canonicalization. Batch/lot/Part selection, preparation, exact digest approval, cancellation, truthful run certainty/cursor and progress/terminal worker examples traverse actual HTTP in server tests.

`src/json.ts` is a server-only strict JSON/retained-document helper; browser consumers import the runtime schemas/client, not its Node byte-count helper. It rejects decoded duplicate keys even if their values match, reserved prototype keys, unsafe/nonfinite numeric literals, comments/trailing commas, depth over 64 and payloads over 256 KiB. Canonical v1 preserves Unicode rather than silently normalizing human text; its exact Unicode UTF-8/hash vector is retained in `vectors/canonical-v1.json` and round-tripped through real PG. Canonicalization is not a general JSON serializer: domain number values must already be schema-authorized strings, and schema-defined sets must be sorted by the owning command.

The narrowed worker envelope supports only progress/running or terminal/completed/interrupted messages. Authentication, sequence ownership, input freshness, proposal/question shapes and accepted-result persistence belong to T06. These examples must not be mistaken for a complete provider protocol or approval grant. `RunSnapshot` is the minimum polling/certainty contract; operation/effect detail and recovery actions are extended with T03/T04 through the coordinator, preserving version compatibility rather than silently interpreting unknown fields. Follow the server's [boundary-focused testing guidelines](../intake-server/TESTING.md) when changing these schemas. The `.cjs` generator runs directly on pinned Node and consumes this runtime TypeScript schema source through Node's native type stripping, not an application/bundler loader.
